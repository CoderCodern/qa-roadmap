## Intro

<En>
Functions are the core building block of clean test code. Every reusable assertion helper, every page action, and every data generator in a test suite is a function. Learning to write small, focused, well-named functions — and to use parameters and return values correctly — is one of the highest-leverage skills in test automation.
</En>
<Vi>
Hàm là khối xây dựng cốt lõi của code test gọn sạch. Mọi assertion helper tái sử dụng, mọi hành động trang, và mọi trình tạo dữ liệu trong bộ test đều là một hàm. Học cách viết các hàm nhỏ, tập trung, có tên rõ ràng — và dùng tham số và giá trị trả về đúng cách — là một trong những kỹ năng có đòn bẩy cao nhất trong tự động hoá test.
</Vi>

## Concept

<En>
**Function anatomy:**
```python
def function_name(param1, param2="default") -> ReturnType:
    """One-line summary (optional docstring)."""
    # body
    return result
```

**Key concepts:**

**Positional vs keyword arguments:** Call with position (`add(2, 3)`) or name (`add(b=3, a=2)`). Keyword arguments are self-documenting.

**Default arguments:** `def login(email, timeout=30)` — callers can omit `timeout` and get 30. Never use mutable defaults (lists, dicts) — they persist between calls.

**Return values:** A function that returns nothing implicitly returns `None`. Be explicit with `return` when the value matters.

**Type hints** (Python 3.5+): `def get_user(id: int) -> dict:` — not enforced at runtime but essential for readability and IDE support.

**Single Responsibility:** Each function should do one thing. If you need to describe a function with "and", split it.

**Helper functions in tests:** Small helpers like `make_user_payload(email, role="viewer")` prevent repetition across test cases and make test setup readable.
</En>
<Vi>
**Cấu trúc hàm:**
```python
def function_name(param1, param2="default") -> ReturnType:
    """Tóm tắt một dòng (docstring tùy chọn)."""
    # thân hàm
    return result
```

**Các khái niệm quan trọng:**

**Tham số vị trí vs từ khoá:** Gọi theo vị trí (`add(2, 3)`) hoặc theo tên (`add(b=3, a=2)`). Tham số từ khoá tự ghi lại ý nghĩa.

**Tham số mặc định:** `def login(email, timeout=30)` — người gọi có thể bỏ qua `timeout` và nhận 30. Đừng bao giờ dùng mặc định có thể thay đổi (list, dict) — chúng tồn tại giữa các lần gọi.

**Giá trị trả về:** Một hàm không trả về gì mặc nhiên trả về `None`. Hãy rõ ràng với `return` khi giá trị quan trọng.

**Type hints** (Python 3.5+): `def get_user(id: int) -> dict:` — không bắt buộc lúc runtime nhưng thiết yếu cho khả năng đọc và hỗ trợ IDE.

**Trách nhiệm đơn:** Mỗi hàm nên làm một việc. Nếu bạn cần mô tả một hàm với "và", hãy tách nó ra.
</Vi>

## Code / Demo

**Pattern 1 — Basic function anatomy: parameters, defaults, return values**

<En>Every function has a name, parameters (optional), a body, and a return value. Default parameters let callers skip arguments they don't need to customise — but never use a mutable object as a default.</En>
<Vi>Mỗi hàm có tên, tham số (tuỳ chọn), thân hàm và giá trị trả về. Tham số mặc định cho phép người gọi bỏ qua các đối số không cần tuỳ chỉnh — nhưng đừng bao giờ dùng đối tượng có thể thay đổi làm mặc định.</Vi>

<CodePlayground code={`
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

def add(a, b):
    return a + b

def is_success_status(code):
    return 200 <= code < 300

print(greet("Alice"))             # uses default greeting
print(greet("Bob", "Hi"))        # overrides default
print(add(3, 4))

assert greet("Alice") == "Hello, Alice!"
assert greet("Bob", "Hi") == "Hi, Bob!"
assert add(3, 4) == 7
assert is_success_status(200)
assert is_success_status(201)
assert not is_success_status(404)
print("Pattern 1 ok — basic functions")
`} />

**Pattern 2 — Keyword arguments and type hints**

<En>Calling with keyword arguments (`make_payload(email=..., password=...)`) makes the call self-documenting. Type hints document expected types without enforcing them at runtime.</En>
<Vi>Gọi với đối số từ khoá (`make_payload(email=..., password=...)`) giúp lời gọi tự giải thích. Type hint ghi lại kiểu dự kiến mà không bắt buộc chúng lúc runtime.</Vi>

<CodePlayground code={`
def make_login_payload(email: str, password: str, remember: bool = False) -> dict:
    return {"email": email, "password": password, "remember": remember}

def build_headers(token: str, content_type: str = "application/json") -> dict:
    return {
        "Authorization": f"Bearer {token}",
        "Content-Type":  content_type,
    }

# positional call
p1 = make_login_payload("alice@example.com", "Pass123")
# keyword call — order doesn't matter, reads like prose
p2 = make_login_payload(password="Pass123", email="alice@example.com", remember=True)

assert p1["email"] == "alice@example.com"
assert p2["remember"] is True

headers = build_headers("my-secret-token")
assert headers["Authorization"] == "Bearer my-secret-token"
assert headers["Content-Type"]  == "application/json"

print(f"Payload: {p1}")
print(f"Headers: {headers}")
print("Pattern 2 ok — keyword args and type hints")
`} />

**Pattern 3 — Assertion helpers and data generators**

<En>Small helpers like `assert_response_ok` wrap repeated assertion logic into one reusable call, keeping individual tests short. Data generators like `make_unique_email` produce fresh test inputs every time they are called.</En>
<Vi>Các helper nhỏ như `assert_response_ok` gói gọn logic assertion lặp lại thành một lời gọi tái sử dụng, giữ cho mỗi test ngắn gọn. Các trình tạo dữ liệu như `make_unique_email` tạo ra dữ liệu test mới mỗi lần được gọi.</Vi>

<CodePlayground code={`
import time

def is_success_status(code):
    return 200 <= code < 300

def assert_response_ok(status_code, body):
    assert is_success_status(status_code), \
        f"Expected 2xx status but got {status_code}"
    assert body is not None, "Response body must not be None"

def make_unique_email(prefix="test"):
    ts = int(time.time() * 1000) % 100000
    return f"{prefix}+{ts}@example.com"

# assertion helper
assert_response_ok(200, {"token": "abc123"})
assert_response_ok(201, {"id": 42})

# data generator
email = make_unique_email("qa")
assert email.startswith("qa+")
assert email.endswith("@example.com")
print(f"Generated: {email}")

# assert_response_ok rejects bad cases correctly
try:
    assert_response_ok(404, {"error": "not found"})
    print("ERROR: should have raised")
except AssertionError as e:
    print(f"Caught expected failure: {e}")

print("Pattern 3 ok — assertion helpers and data generators")
`} />

**Pattern 4 — Mutable default argument trap**

<En>A default value is evaluated once when the function is defined — not on each call. If you use a mutable default like `[]`, all callers share the same list. Fix it by using `None` and creating a fresh object inside the body.</En>
<Vi>Giá trị mặc định được tính một lần khi hàm được định nghĩa — không phải mỗi lần gọi. Nếu bạn dùng mặc định có thể thay đổi như `[]`, tất cả người gọi chia sẻ cùng một list. Sửa bằng cách dùng `None` và tạo đối tượng mới bên trong thân hàm.</Vi>

<CodePlayground code={`
# WRONG — shared mutable default
def broken_append(item, lst=[]):
    lst.append(item)
    return lst

r1 = broken_append("a")
r2 = broken_append("b")
print(f"broken r1={r1}, r2={r2}")  # both show ['a', 'b'] — surprising!
assert r1 is r2  # same list object!

# CORRECT — use None, create fresh list inside
def safe_append(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

s1 = safe_append("a")
s2 = safe_append("b")
print(f"safe   s1={s1}, s2={s2}")  # ['a'] and ['b'] — independent
assert s1 == ["a"]
assert s2 == ["b"]
assert s1 is not s2
print("Pattern 4 ok — mutable default trap fixed")
`} />

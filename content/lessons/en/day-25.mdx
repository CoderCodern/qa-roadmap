## Intro

<En>
Finding elements is only the first step. The next step is **acting** on them — clicking buttons, typing into inputs, selecting dropdown options, checking checkboxes, uploading files, pressing keyboard shortcuts. Playwright calls these **actions**, and they all share one critical behaviour: **they auto-wait** before executing.

Before every action, Playwright verifies that the target element is:
1. Attached to the DOM
2. Visible (not hidden, not `display: none`)
3. Stable (not animating or moving)
4. Enabled (not disabled)
5. Receives pointer events (not covered by another element)

This means you almost never need to add `time.sleep()` between actions.
</En>
<Vi>
Tìm phần tử chỉ là bước đầu tiên. Bước tiếp theo là **thao tác** với chúng — nhấp nút, gõ vào input, chọn trong dropdown, đánh dấu checkbox, tải lên file, nhấn phím tắt. Playwright gọi đây là **actions**, và tất cả đều có một hành vi quan trọng: **tự động chờ** trước khi thực thi.

Trước mỗi action, Playwright xác minh rằng phần tử đích:
1. Được gắn vào DOM
2. Hiển thị (không bị ẩn, không có `display: none`)
3. Ổn định (không đang animate hoặc di chuyển)
4. Được bật (không bị disabled)
5. Nhận được sự kiện con trỏ (không bị phần tử khác che)

Điều này có nghĩa là bạn hầu như không bao giờ cần thêm `time.sleep()` giữa các action.
</Vi>

## Concept

<En>
**The core actions — full reference:**

**Mouse actions:**
```python
locator.click()                         # single left click
locator.dblclick()                      # double click
locator.right_click()                   # right click (context menu)
locator.hover()                         # move mouse over (for tooltips/dropdowns)
locator.click(button="middle")          # middle click
locator.click(modifiers=["Shift"])      # shift+click (e.g., range select)
locator.click(modifiers=["Control"])    # ctrl+click (multi-select in tables)
locator.click(position={"x": 10, "y": 5})  # click at specific pixel offset within element
locator.tap()                           # mobile tap event (use when testing touch screens)
```

**Why `locator.tap()` matters:** On mobile browsers or responsive test configurations, `tap()` sends a touch event instead of a mouse click. Some mobile frameworks only respond to touch events, so using `tap()` instead of `click()` gives you realistic mobile simulation.

**Text input actions:**
```python
locator.fill("Hello World")     # clear and type (most common — fast, no keystroke events)
locator.type("Hello World")     # simulate keystrokes one by one (triggers keydown/keyup events)
locator.press("Enter")          # press a single named key
locator.press("Control+A")      # keyboard shortcut (select all)
locator.press("Shift+Tab")      # shift+tab (move focus backwards)
locator.press("Escape")         # dismiss modals, dropdowns, autocomplete
locator.clear()                 # clear input without typing anything

page.keyboard.press("Tab")      # page-level keyboard (when no specific element has focus)
page.keyboard.press("F5")       # function keys — refresh the page
page.keyboard.type("text")      # type at whatever has focus currently
```

**When to use `type()` vs `fill()`:** Use `fill()` for 95% of cases — it's faster and sufficient. Use `type()` when the application has keystroke listeners that trigger as you type (e.g., autocomplete suggestions that appear letter-by-letter, character counting inputs, or real-time validation).

**Keyboard shortcuts with `locator.press()`:** Key names follow the `KeyboardEvent.key` standard values — `Control`, `Shift`, `Alt`, `Meta` (Cmd on Mac). Combine them with `+` as the separator:
```python
locator.press("Control+A")   # select all text in the input
locator.press("Control+C")   # copy
locator.press("Control+Z")   # undo
locator.press("Tab")         # move focus to next field
locator.press("Escape")      # close modal or dismiss autocomplete
locator.press("ArrowDown")   # navigate dropdown options
```

**Form control actions:**
```python
# Checkboxes and radio buttons
locator.check()               # ensure checkbox IS checked (idempotent — safe to call even if already checked)
locator.uncheck()             # ensure checkbox IS NOT checked (idempotent)
locator.set_checked(True)     # programmatic set — equivalent to check()
locator.set_checked(False)    # programmatic set — equivalent to uncheck()

# Why prefer check() over click() for checkboxes:
# click() TOGGLES the current state — unreliable if state is unknown
# check() GUARANTEES the checkbox ends up checked — much more expressive and safe

# Select dropdowns
page.select_option("select#country", "us")               # by value attribute
page.select_option("select#country", label="United States")  # by visible text (most readable)
page.select_option("select#country", index=0)            # by 0-based position
page.select_option("select#size", ["s", "m"])            # multi-select (list of values)

# File upload — bypasses the OS file picker completely
page.locator("input[type='file']").set_input_files("path/to/file.pdf")
page.locator("input[type='file']").set_input_files(["file1.pdf", "file2.pdf"])  # multiple files
page.locator("input[type='file']").set_input_files([])   # clear file selection
```

**Scroll actions:**
```python
page.mouse.wheel(0, 300)              # scroll down 300px on the page
page.mouse.wheel(0, -300)             # scroll up 300px
locator.scroll_into_view_if_needed()  # scroll so element is in the viewport before acting
```

**Drag and drop:**
```python
page.drag_and_drop("#source", "#target")   # using CSS selectors
locator.drag_to(other_locator)             # using locators (preferred — waits for both elements)
# drag_to() is useful for: sortable lists, kanban boards, file uploads via drag, sliders
```

**Forcing actions (last resort):**
If Playwright's actionability checks prevent an action (e.g., element is covered by a cookie banner), you can bypass them with `force=True` — but this should be rare. The correct fix is usually to dismiss the overlay first:
```python
locator.click(force=True)   # skips all actionability checks — the element may not even be interactable
# Only use when: the overlay is intentional and dismissing it isn't possible in test context
```

**Reading values back:**
```python
locator.text_content()         # all text including text in child elements
locator.inner_text()           # visible text only — respects CSS display:none
locator.get_attribute("href")  # returns the HTML attribute value (initial value in DOM)
locator.input_value()          # current value of an input/textarea/select (what JS sees)
locator.is_checked()           # True/False for checkbox or radio button
locator.is_enabled()           # True/False — False means the form element is disabled
locator.is_visible()           # True/False — one-shot check, no retry (use sparingly)
```

**`input_value()` vs `get_attribute('value')`:** `input_value()` returns the live JavaScript value of the input — what the user sees right now. `get_attribute('value')` returns the initial HTML attribute from the markup, which doesn't update when the user types. Always use `input_value()` to read what's in an input field.

**`is_visible()` vs `expect(locator).to_be_visible()`:** `is_visible()` queries the DOM once and returns a boolean immediately — no retry. If the element isn't ready yet, it returns `False`. `expect(locator).to_be_visible()` polls every ~100ms and retries for up to 5 seconds — reliable for async content. Use `expect()` in assertions.
</En>
<Vi>
**Các action cốt lõi — tham chiếu đầy đủ:**

**Thao tác chuột:**
```python
locator.click()                         # nhấp trái đơn
locator.dblclick()                      # nhấp đúp
locator.right_click()                   # nhấp phải (mở context menu)
locator.hover()                         # di chuột qua (hiện tooltip/dropdown)
locator.click(modifiers=["Shift"])      # shift+click (chọn vùng)
locator.click(modifiers=["Control"])    # ctrl+click (chọn nhiều)
locator.click(position={"x": 10, "y": 5})  # nhấp tại vị trí pixel cụ thể
locator.tap()                           # sự kiện chạm (dùng khi test mobile)
```

**Tại sao `locator.tap()` quan trọng:** Trên trình duyệt mobile hoặc cấu hình test responsive, `tap()` gửi touch event thay vì mouse click. Một số framework mobile chỉ phản hồi touch event, vì vậy dùng `tap()` thay vì `click()` cho bạn mô phỏng mobile thực tế.

**Nhập văn bản:**
```python
locator.fill("Hello World")     # xóa và gõ (phổ biến nhất — nhanh, không trigger keystroke events)
locator.type("Hello World")     # giả lập từng phím (trigger keydown/keyup events)
locator.press("Enter")          # nhấn một phím
locator.press("Control+A")      # phím tắt (chọn tất cả)
locator.press("Shift+Tab")      # shift+tab (di chuyển focus ngược)
locator.press("Escape")         # đóng modal, dropdown, autocomplete
locator.clear()                 # xóa input mà không gõ gì

page.keyboard.press("Tab")      # bàn phím cấp trang (khi không có phần tử cụ thể nào được focus)
page.keyboard.type("text")      # gõ tại vị trí đang được focus
```

**Khi nào dùng `type()` vs `fill()`:** Dùng `fill()` cho 95% trường hợp — nhanh hơn và đủ dùng. Dùng `type()` khi ứng dụng có keystroke listener kích hoạt khi bạn gõ (ví dụ: gợi ý autocomplete, đếm ký tự thời gian thực, validation ngay khi nhập).

**Phím tắt với `locator.press()`:** Tên phím theo chuẩn `KeyboardEvent.key` — `Control`, `Shift`, `Alt`, `Meta` (Cmd trên Mac). Kết hợp bằng dấu `+`:
```python
locator.press("Control+A")   # chọn tất cả văn bản trong input
locator.press("Control+Z")   # hoàn tác
locator.press("Tab")         # chuyển focus sang field tiếp theo
locator.press("Escape")      # đóng modal hoặc bỏ autocomplete
locator.press("ArrowDown")   # điều hướng trong dropdown
```

**Điều khiển form:**
```python
# Checkbox và radio button
locator.check()               # đảm bảo checkbox ĐƯỢC đánh dấu (idempotent — an toàn dù đã check rồi)
locator.uncheck()             # đảm bảo checkbox KHÔNG được đánh dấu (idempotent)
locator.set_checked(True)     # đặt lập trình — tương đương check()
locator.set_checked(False)    # đặt lập trình — tương đương uncheck()

# Tại sao dùng check() thay vì click() cho checkbox:
# click() CHUYỂN ĐỔI trạng thái hiện tại — không đáng tin nếu trạng thái không biết trước
# check() ĐẢM BẢO checkbox kết thúc ở trạng thái được đánh dấu — rõ ràng và an toàn hơn

# Chọn dropdown
page.select_option("select#country", "us")                   # theo value attribute
page.select_option("select#country", label="United States")  # theo text hiển thị (dễ đọc nhất)
page.select_option("select#country", index=0)                # theo vị trí 0-based
page.select_option("select#size", ["s", "m"])                # multi-select (list các value)

# Upload file — bỏ qua dialog chọn file của OS hoàn toàn
page.locator("input[type='file']").set_input_files("path/to/file.pdf")
page.locator("input[type='file']").set_input_files(["file1.pdf", "file2.pdf"])  # nhiều file
page.locator("input[type='file']").set_input_files([])   # xóa file đã chọn
```

**Kéo và thả:**
```python
page.drag_and_drop("#source", "#target")   # dùng CSS selector
locator.drag_to(other_locator)             # dùng locator (ưu tiên — chờ cả hai phần tử)
# drag_to() hữu ích cho: danh sách có thể sắp xếp, kanban board, upload file bằng kéo thả, slider
```

```python
# demo_actions_login.py
# Run with: python demo_actions_login.py
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()

    # Navigate to the login page
    page.goto("https://practicesoftwaretesting.com/auth/login")

    # Fill email — uses get_by_label() for resilient, accessible targeting
    page.get_by_label("Email").fill("customer@practicesoftwaretesting.com")

    # Fill password — fill() clears the field first, then sets value
    page.get_by_label("Password").fill("welcome01")

    # Click the submit button — Playwright auto-waits for it to be enabled and visible
    page.get_by_role("button", name="Login").click()

    # After login, Playwright needs to wait explicitly for the navigation to complete
    # wait_for_url() polls until the URL pattern matches or times out
    page.wait_for_url("**/account")
    print(f"Logged in! Current URL: {page.url}")

    # Assert the account heading is visible — confirms we are on the right page
    expect(page.get_by_role("heading", name="My account")).to_be_visible()
    print("Login successful!")

    browser.close()

# Expected output:
# Logged in! Current URL: https://practicesoftwaretesting.com/account
# Login successful!
```

```python
# demo_actions_form.py
# Demonstrates check, select_option, and keyboard actions
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://practicesoftwaretesting.com")

    # --- Hover to open a dropdown navigation menu ---
    # hover() moves the mouse over the element to trigger CSS :hover styles
    categories = page.get_by_role("link", name="Categories")
    categories.hover()
    page.wait_for_timeout(500)  # brief pause for CSS transition to complete
    print(f"Hovered over Categories")

    # --- Use the search box with keyboard shortcut ---
    search = page.get_by_role("textbox", name="Search")
    search.click()                  # focus the input first
    search.fill("Hammer")           # clear and type the search term
    search.press("Enter")           # press Enter to submit (same as clicking Search button)

    # Wait for search API to return results before counting cards
    page.wait_for_load_state("networkidle")
    results = page.locator(".card")
    print(f"Search results for 'Hammer': {results.count()}")

    # --- Navigate to contact form to test a select dropdown ---
    page.goto("https://practicesoftwaretesting.com/contact")

    # Fill text fields — get_by_label() matches the visible label text
    page.get_by_label("First name").fill("Test")
    page.get_by_label("Last name").fill("User")
    page.get_by_label("Email").fill("test@example.com")

    # Select a dropdown option by its visible label text (what the user sees)
    # label= is the most readable option — avoids coupling to internal value attributes
    page.select_option("select[name='subject']", label="Webmaster")
    print("Selected subject: Webmaster")

    # Fill the message textarea — same fill() API works for multi-line textareas
    page.get_by_label("Message").fill("This is an automated test message.")
    print("Form filled successfully!")

    browser.close()

# Expected output:
# Hovered over Categories
# Search results for 'Hammer': 1
# Selected subject: Webmaster
# Form filled successfully!
```

```python
# tests/test_actions.py
# Run with: pytest tests/test_actions.py -v
from playwright.sync_api import Page, expect

BASE = "https://practicesoftwaretesting.com"

def test_search_returns_results(page: Page):
    """Typing in search and pressing Enter should return product results."""
    page.goto(BASE)
    search = page.get_by_role("textbox", name="Search")
    search.fill("Pliers")
    search.press("Enter")
    page.wait_for_load_state("networkidle")

    cards = page.locator(".card")
    assert cards.count() > 0, "Expected search results"

def test_login_with_valid_credentials(page: Page):
    """Valid credentials should navigate to the account page."""
    page.goto(f"{BASE}/auth/login")
    page.get_by_label("Email").fill("customer@practicesoftwaretesting.com")
    page.get_by_label("Password").fill("welcome01")
    page.get_by_role("button", name="Login").click()
    expect(page).to_have_url(f"{BASE}/account")

def test_login_with_wrong_password_shows_error(page: Page):
    """Wrong password should show an error message — negative test pattern.

    Negative tests verify that the system correctly rejects bad input.
    The pattern here is: perform the bad action, then assert an error state exists.
    We use a broad selector (.alert-danger, .error, [role='alert']) because
    different UI frameworks use different class names for error messages —
    at least one of these should match the site's error element.
    """
    page.goto(f"{BASE}/auth/login")
    page.get_by_label("Email").fill("customer@practicesoftwaretesting.com")
    page.get_by_label("Password").fill("wrongpassword")
    page.get_by_role("button", name="Login").click()
    # An error/alert should appear — wait for it with expect() which retries
    error = page.locator(".alert-danger, .error, [role='alert']")
    expect(error).to_be_visible()
```

## Intro

<En>
Running Playwright scripts manually is a start, but professional automation means integrating Playwright with **pytest** — the industry-standard Python test runner. pytest tracks pass/fail results, produces reports, handles test setup and teardown, and integrates with CI pipelines.

The `pytest-playwright` plugin bridges the two: it registers Playwright fixtures (`page`, `browser`, `context`) that pytest injects automatically into your test functions. You never write `sync_playwright()` in a test file — pytest handles it all. Today you write your first real, structured Playwright test.
</En>
<Vi>
Chạy script Playwright thủ công là bước đầu, nhưng tự động hoá chuyên nghiệp có nghĩa là tích hợp Playwright với **pytest** — test runner Python tiêu chuẩn trong ngành. pytest theo dõi kết quả pass/fail, tạo báo cáo, xử lý setup và teardown, và tích hợp với pipeline CI.

Plugin `pytest-playwright` kết nối cả hai: nó đăng ký các fixture Playwright (`page`, `browser`, `context`) mà pytest tự động inject vào hàm test của bạn. Bạn không bao giờ phải viết `sync_playwright()` trong file test — pytest xử lý tất cả. Hôm nay bạn viết Playwright test thực sự đầu tiên, có cấu trúc.
</Vi>

## Concept

<En>
**How pytest-playwright fixtures work:**

When you add `page` as a parameter to a test function, pytest-playwright:
1. Launches a browser (Chromium by default)
2. Creates a fresh BrowserContext (isolated session)
3. Opens a new Page (tab)
4. Passes it to your test
5. Closes context and browser after the test finishes — automatically

You never call `browser.close()` or `context.close()` in your tests. The fixture handles it via a teardown phase that runs after `yield`.

**Available fixtures and their scopes:**

| Fixture | Scope | What it gives you |
|---------|-------|------------------|
| `playwright` | session | The Playwright instance |
| `browser` | session | A launched browser (shared across all tests) |
| `context` | function | A fresh isolated BrowserContext per test |
| `page` | function | A ready Page inside that context |

**Why are `browser` and `context` different scopes?** The browser binary startup is expensive (~1–2 seconds), so it is shared across the whole test session. The context (session data) is cheap to create and must be fresh per test to prevent pollution — a cookie set in `test_login` should never appear in `test_checkout`. The `page` fixture is also function-scoped because it lives inside a context.

**Playwright's `expect()` assertions — smarter than `assert`:**

```python
from playwright.sync_api import expect

# These poll and retry until true (default timeout: 5 seconds)
expect(page).to_have_title("My App")           # check page title
expect(page).to_have_url("https://app.com/")   # check current URL
expect(locator).to_be_visible()                # element is visible in the DOM
expect(locator).to_be_hidden()                 # element is not visible
expect(locator).to_contain_text("Welcome")     # element contains text (partial match)
expect(locator).to_have_text("Exact text")     # element exact text match
expect(locator).to_be_enabled()                # button/input is not disabled
expect(locator).to_be_checked()               # checkbox is checked
expect(locator).to_have_count(3)              # exactly 3 elements match
expect(locator).to_have_value("admin@x.com")  # input value
expect(locator).to_have_attribute("href", "/docs")  # element has attribute with value
expect(locator).to_be_focused()               # element currently has keyboard focus
expect(locator).not_to_be_visible()           # negation — element must NOT be visible
```

`expect()` is better than a plain `assert` because it **retries** — if the page is still loading or animating, it waits up to the timeout before failing. A plain `assert locator.is_visible()` fails immediately if the element isn't ready yet, producing flaky tests that fail randomly depending on page load speed.

**Install and run:**
```bash
pip install pytest-playwright
playwright install chromium

# Run all tests in the tests/ directory with verbose output
pytest tests/ -v

# Run headed (show browser window — useful for debugging)
pytest tests/ --headed

# Run in Firefox instead of Chromium
pytest tests/ --browser firefox

# Run in both Chromium and Firefox in one command
pytest tests/ --browser chromium --browser firefox

# Run with slow-mo (ms delay between actions — combine with --headed)
pytest tests/ --headed --slowmo 500
```

**File structure:**
```
project/
├── tests/
│   ├── conftest.py        ← global fixtures and config (optional)
│   └── test_example.py    ← test file (must start with test_)
└── pytest.ini             ← pytest config (optional)
```
</En>
<Vi>
**Cách fixture pytest-playwright hoạt động:**

Khi bạn thêm `page` làm tham số vào hàm test, pytest-playwright:
1. Khởi chạy trình duyệt (Chromium mặc định)
2. Tạo BrowserContext mới (phiên độc lập) cho mỗi test
3. Mở Page mới (tab)
4. Truyền nó vào test của bạn
5. Đóng context và trình duyệt sau khi test kết thúc — tự động

**Các fixture có sẵn và phạm vi của chúng:**

| Fixture | Phạm vi | Cung cấp gì |
|---------|-------|------------------|
| `playwright` | session | Instance Playwright |
| `browser` | session | Trình duyệt đã khởi chạy (dùng chung cho tất cả test) |
| `context` | function | BrowserContext mới mỗi test |
| `page` | function | Page sẵn sàng trong context đó |

**Tại sao `browser` và `context` có phạm vi khác nhau?** Khởi động browser binary tốn kém (~1-2 giây), nên được chia sẻ cho cả phiên test. Context (dữ liệu phiên) rẻ để tạo và phải mới cho mỗi test để ngăn ô nhiễm — cookie được đặt trong `test_login` không bao giờ nên xuất hiện trong `test_checkout`.

**Assertion `expect()` của Playwright:**
```python
from playwright.sync_api import expect

expect(page).to_have_title("My App")
expect(page).to_have_url("https://app.com/")
expect(locator).to_be_visible()
expect(locator).to_contain_text("Welcome")
expect(locator).to_have_count(3)
expect(locator).to_have_attribute("href", "/docs")
expect(locator).to_be_focused()
expect(locator).not_to_be_visible()
```

`expect()` tốt hơn `assert` thuần vì nó **thử lại** — nếu trang vẫn đang tải hoặc có animation, nó chờ đến khi hết timeout mới báo lỗi. `assert locator.is_visible()` thất bại ngay lập tức nếu phần tử chưa sẵn sàng.

**Cài đặt và chạy:**
```bash
pip install pytest-playwright
playwright install chromium
pytest tests/ -v                        # chạy tất cả test với output chi tiết
pytest tests/ --headed                  # hiện cửa sổ trình duyệt
pytest tests/ --browser firefox         # dùng Firefox thay vì Chromium
pytest tests/ --browser chromium --browser firefox  # chạy cả hai trình duyệt
```

<En>

**Part 1 — Your first pytest-playwright test file**

</En>
<Vi>

**Phần 1 — File test pytest-playwright đầu tiên của bạn**

</Vi>

```python
# tests/test_example_com.py
# Run with: pytest tests/test_example_com.py -v
import pytest
from playwright.sync_api import Page, expect

# The `page` parameter is automatically injected by pytest-playwright.
# No setup/teardown code needed — the fixture handles everything.
# Each test function gets a brand new, isolated Page in its own BrowserContext.

# What this test does: visits example.com and checks the <title> tag value
def test_page_has_correct_title(page: Page):
    """The page title should be 'Example Domain'."""
    page.goto("https://example.com")
    # to_have_title retries up to 5s — handles slow DNS or redirects gracefully
    expect(page).to_have_title("Example Domain")

# What this test does: finds the <h1> heading and checks it is both visible and correct
def test_heading_is_visible_and_correct(page: Page):
    """The h1 heading should be visible and contain the right text."""
    page.goto("https://example.com")
    heading = page.locator("h1")
    expect(heading).to_be_visible()
    expect(heading).to_contain_text("Example Domain")

# What this test does: finds the info link and validates its href is a valid https URL
def test_more_info_link_exists_and_has_href(page: Page):
    """The 'More information' link should exist and point to an https URL."""
    page.goto("https://example.com")
    link = page.locator("a", has_text="More information")
    expect(link).to_be_visible()
    href = link.get_attribute("href")
    assert href is not None, "Link should have an href"
    assert href.startswith("https://"), f"Expected https link, got: {href}"

# What this test does: confirms example.com has no form elements (it's purely static)
def test_page_has_no_form_elements(page: Page):
    """Example.com is a static page — no forms expected."""
    page.goto("https://example.com")
    expect(page.locator("form")).to_have_count(0)

# What this test does: confirms the URL resolves to the canonical form with trailing slash
def test_page_url_is_canonical(page: Page):
    """URL should resolve to https://example.com/ (with trailing slash)."""
    page.goto("https://example.com")
    expect(page).to_have_url("https://example.com/")

# Expected output when running: pytest tests/test_example_com.py -v
# tests/test_example_com.py::test_page_has_correct_title              PASSED
# tests/test_example_com.py::test_heading_is_visible_and_correct      PASSED
# tests/test_example_com.py::test_more_info_link_exists_and_has_href  PASSED
# tests/test_example_com.py::test_page_has_no_form_elements           PASSED
# tests/test_example_com.py::test_page_url_is_canonical               PASSED
# 5 passed in X.XXs
```

**Phần 2 — conftest.py: tùy chỉnh browser context**

</Vi>

```python
# conftest.py  (place at project root or tests/ directory)
import pytest

# browser_context_args overrides the BrowserContext options for ALL tests.
# Use this approach (conftest.py) when you want the config to apply to every
# test that uses the `context` or `page` fixture — no changes to individual files.
#
# Alternative: use pytest.ini with [pytest] base_url = https://example.com
# for the base_url setting. conftest.py is better for viewport, locale, and
# more complex options that pytest.ini cannot express as simple key=value pairs.
@pytest.fixture(scope="session")
def browser_context_args(browser_context_args):
    return {
        **browser_context_args,          # preserve any existing args
        "viewport": {"width": 1280, "height": 720},
        # "base_url": "https://example.com",   # uncomment to use page.goto("/")
        # "locale": "en-US",                   # override browser locale
        # "timezone_id": "America/New_York",   # override timezone
    }
```

```python
from playwright.sync_api import Page, expect

def test_home_page_title(page: Page):
    # With base_url set, goto("/") navigates to https://example.com/
    # This is cleaner than repeating the full URL in every test
    page.goto("/")
    expect(page).to_have_title("Example Domain")
    # Expected: PASSED — title matches exactly

def test_full_url_still_works(page: Page):
    # Full absolute URLs always work regardless of base_url setting
    # Use full URLs when navigating to a completely different domain
    page.goto("https://playwright.dev/")
    expect(page).to_have_url("https://playwright.dev/")
    # Expected: PASSED — URL matches after navigation
```

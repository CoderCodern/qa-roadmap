## Intro

<En>
Dicts and sets are the two remaining essential Python data structures for QA work. Dicts are how JSON responses look once parsed — every API response body is a dict (or a list of dicts). Sets give you instant membership testing and deduplication. Mastering these two types means you can navigate any API response and reason about any collection of values.
</En>
<Vi>
Dict và set là hai cấu trúc dữ liệu thiết yếu còn lại của Python cho công việc QA. Dict là cách các JSON response trông sau khi được phân tích — mọi API response body đều là một dict (hoặc danh sách dict). Set cho phép kiểm tra thành viên tức thì và loại bỏ trùng lặp. Thành thạo hai kiểu này có nghĩa là bạn có thể điều hướng bất kỳ API response nào và suy luận về bất kỳ tập hợp giá trị nào.
</Vi>

## Concept

<En>
**Dict — key → value mapping, ordered (Python 3.7+):**
```python
user = {"id": 1, "email": "alice@example.com", "role": "admin"}
user["email"]               # access by key
user.get("phone", "N/A")   # safe access with default
user["phone"] = "555-1234" # add/update key
del user["phone"]           # remove key
"email" in user             # membership check
user.keys()                 # all keys
user.values()               # all values
user.items()                # (key, value) pairs for iteration
```

**Nested dicts** (common in JSON):
```python
response = {"data": {"user": {"id": 1}}}
user_id = response["data"]["user"]["id"]  # chain access
```

**Set — unordered, unique elements:**
```python
roles = {"admin", "editor", "viewer"}
"admin" in roles    # O(1) lookup
roles.add("owner")
roles.discard("viewer")  # remove if present (no error if absent)
set_a & set_b       # intersection
set_a | set_b       # union
set_a - set_b       # difference
```

**Dict comprehension:**
```python
{item["id"]: item["name"] for item in items}
```

**When to use each:**
- **dict** — structured data with named fields (API responses, test configs)
- **set** — unordered unique values (allowed roles, unique IDs, deduplication)
</En>
<Vi>
**Dict — ánh xạ key → value, có thứ tự (Python 3.7+):**
```python
user = {"id": 1, "email": "alice@example.com", "role": "admin"}
user["email"]               # truy cập theo key
user.get("phone", "N/A")   # truy cập an toàn với mặc định
"email" in user             # kiểm tra thành viên
user.items()                # cặp (key, value) để lặp
```

**Dict lồng nhau** (phổ biến trong JSON):
```python
response = {"data": {"user": {"id": 1}}}
user_id = response["data"]["user"]["id"]
```

**Set — không có thứ tự, các phần tử duy nhất:**
```python
roles = {"admin", "editor", "viewer"}
"admin" in roles    # tra cứu O(1)
roles.add("owner")
set_a & set_b       # giao
set_a | set_b       # hợp
set_a - set_b       # hiệu
```

**Khi nào dùng mỗi cái:**
- **dict** — dữ liệu có cấu trúc với các trường được đặt tên (API response, cấu hình test)
- **set** — giá trị duy nhất không có thứ tự (role được phép, ID duy nhất, loại bỏ trùng lặp)
</Vi>

## Code / Demo

**Pattern 1 — Dict basics: access, update, delete, iterate**

<En>Dicts map keys to values. Access a key with `d[key]` (raises `KeyError` if missing) or iterate all pairs with `.items()`. Add or overwrite a key with `d[key] = value`; delete it with `del d[key]`.</En>
<Vi>Dict ánh xạ key sang value. Truy cập key bằng `d[key]` (ném `KeyError` nếu không có) hoặc lặp qua tất cả cặp bằng `.items()`. Thêm hoặc ghi đè key bằng `d[key] = value`; xoá bằng `del d[key]`.</Vi>

<CodePlayground code={`
user = {"id": 1, "email": "alice@example.com", "role": "admin"}

# Access
print(user["email"])
print(user["role"])

# Add / update
user["phone"] = "555-1234"
user["role"]  = "editor"     # overwrite
assert user["role"]  == "editor"
assert user["phone"] == "555-1234"

# Delete
del user["phone"]
assert "phone" not in user

# Iterate keys, values, pairs
print("Keys:  ", list(user.keys()))
print("Values:", list(user.values()))
for key, value in user.items():
    print(f"  {key}: {value}")

print("Pattern 1 ok — dict basics")
`} />

**Pattern 2 — Nested dicts and safe access with `.get()`**

<En>API responses are usually nested dicts. Chain `[]` to reach deep fields. Use `.get(key, default)` when a field may be absent — it returns the default instead of raising `KeyError`.</En>
<Vi>API response thường là các dict lồng nhau. Nối `[]` để truy cập các trường sâu. Dùng `.get(key, default)` khi trường có thể vắng mặt — nó trả về mặc định thay vì ném `KeyError`.</Vi>

<CodePlayground code={`
response = {
    "status": "success",
    "data": {
        "user": {"id": 42, "email": "alice@example.com"},
        "page": 1,
        "total": 100,
    }
}

# Chained access for nested data
user_id = response["data"]["user"]["id"]
assert user_id == 42
print(f"User ID: {user_id}")

# Safe access — key may or may not exist
phone   = response["data"]["user"].get("phone", "not provided")
token   = response.get("token", None)
page    = response["data"].get("page", 1)

assert phone == "not provided"
assert token is None
assert page  == 1

print(f"Phone: {phone}")
print(f"Token: {token}")
print("Pattern 2 ok — nested dicts and .get()")
`} />

**Pattern 3 — Dict comprehension: build lookup tables**

<En>A dict comprehension `{k: v for item in items}` builds a dict in one line. The most common QA use case is turning a list of objects into an `id → object` lookup so you can fetch any record instantly by ID.</En>
<Vi>Dict comprehension `{k: v for item in items}` xây dựng dict trong một dòng. Trường hợp dùng phổ biến nhất trong QA là chuyển danh sách đối tượng thành bảng tra cứu `id → đối tượng` để lấy bất kỳ bản ghi nào ngay lập tức theo ID.</Vi>

<CodePlayground code={`
users = [
    {"id": 1, "email": "alice@example.com", "role": "admin"},
    {"id": 2, "email": "bob@example.com",   "role": "viewer"},
    {"id": 3, "email": "charlie@example.com","role": "editor"},
]

# id → full user object
user_by_id = {u["id"]: u for u in users}
assert user_by_id[1]["email"] == "alice@example.com"
assert user_by_id[3]["role"]  == "editor"

# id → email only
email_by_id = {u["id"]: u["email"] for u in users}
assert email_by_id[2] == "bob@example.com"

# role → count (how many users per role)
from collections import Counter
role_counts = Counter(u["role"] for u in users)
print(f"user_by_id:  {list(user_by_id.keys())}")
print(f"email_by_id: {email_by_id}")
print(f"role_counts: {dict(role_counts)}")
print("Pattern 3 ok — dict comprehension")
`} />

**Pattern 4 — Sets: membership, deduplication, set operations**

<En>Sets hold unique elements with O(1) membership testing. Use them to validate allowed values, remove duplicates from a list, and find the difference or intersection between two collections.</En>
<Vi>Set chứa các phần tử duy nhất với kiểm tra thành viên O(1). Dùng chúng để kiểm tra giá trị được phép, loại bỏ trùng lặp khỏi list và tìm hiệu hoặc giao giữa hai tập hợp.</Vi>

<CodePlayground code={`
users = [
    {"email": "alice@example.com", "roles": ["admin", "editor"]},
    {"email": "bob@example.com",   "roles": ["viewer"]},
    {"email": "charlie@example.com","roles": ["editor"]},
]

allowed_roles = {"admin", "editor", "viewer", "owner"}

# Membership check — O(1)
assert "admin"   in allowed_roles
assert "hacker" not in allowed_roles

# Validate user roles against allowed set
alice_roles   = set(users[0]["roles"])
unknown_roles = alice_roles - allowed_roles
assert not unknown_roles, f"Unknown roles: {unknown_roles}"

# Deduplication — collect all roles, remove duplicates
all_roles = []
for user in users:
    all_roles.extend(user["roles"])
unique_roles = set(all_roles)
print(f"All roles (with dups): {all_roles}")
print(f"Unique roles:          {unique_roles}")

# Set operations
admin_perms  = {"read", "write", "delete", "admin"}
viewer_perms = {"read"}
shared       = admin_perms & viewer_perms   # intersection
admin_only   = admin_perms - viewer_perms   # difference
all_perms    = admin_perms | viewer_perms   # union

assert shared     == {"read"}
assert "write"    in admin_only
assert "read" not in admin_only
print(f"Shared:     {shared}")
print(f"Admin-only: {admin_only}")
print("Pattern 4 ok — sets")
`} />

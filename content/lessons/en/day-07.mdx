## Concept

<En>
**Week 1 recap — the essential ideas:**

| Concept | Core idea |
|---|---|
| Manual vs Automated | Both needed; automated multiplies your coverage |
| Test types | Smoke → Sanity → Functional → Regression → Exploratory |
| Test design | EP + BVA cover the right input space efficiently |
| Bug lifecycle | New → Assigned → Fixed → Verified → Closed |
| Severity vs Priority | Impact vs Urgency — these are independent dimensions |
| SDLC/STLC | Testing starts at requirements, not after development |
| Test pyramid | Unit (most) → Integration → E2E (fewest) |

**The login form exercise:** Writing test cases for a login form is a classic QA interview exercise. A good candidate covers:
- Happy path (valid email + correct password)
- Invalid email format
- Wrong password
- Empty fields
- SQL injection attempt in email field
- Very long strings
- Correct credentials but account locked
</En>
<Vi>
**Tóm tắt tuần 1 — những ý tưởng thiết yếu:**

| Khái niệm | Ý tưởng cốt lõi |
|---|---|
| Thủ công vs Tự động | Cả hai đều cần; tự động nhân lên độ bao phủ của bạn |
| Loại test | Khói → Tỉnh táo → Chức năng → Hồi quy → Khám phá |
| Thiết kế test | EP + BVA bao phủ không gian đầu vào đúng cách hiệu quả |
| Vòng đời bug | Mới → Được giao → Đã sửa → Đã xác minh → Đã đóng |
| Mức độ nghiêm trọng vs Ưu tiên | Tác động vs Khẩn cấp — đây là các chiều độc lập |
| SDLC/STLC | Kiểm thử bắt đầu từ yêu cầu, không phải sau khi phát triển |
| Kim tự tháp test | Unit (nhiều nhất) → Integration → E2E (ít nhất) |

**Bài tập form đăng nhập:** Viết test case cho form đăng nhập là bài tập phỏng vấn QA kinh điển. Một ứng viên tốt bao gồm:
- Đường dẫn hạnh phúc (email hợp lệ + mật khẩu đúng)
- Định dạng email không hợp lệ
- Mật khẩu sai
- Trường trống
- Thử SQL injection trong trường email
- Chuỗi rất dài
- Thông tin đúng nhưng tài khoản bị khóa
</Vi>

## Code / Demo

```python
# 5 test cases for a login form (using Python pseudocode)
# In Phase 3, you'll implement these as real Playwright tests

login_test_cases = [
    {
        "id": "TC-001",
        "title": "Successful login with valid credentials",
        "steps": [
            "Navigate to /login",
            "Enter email: user@example.com",
            "Enter password: SecurePass123",
            "Click Login"
        ],
        "expected": "Redirected to /dashboard, welcome message visible",
        "type": "Functional"
    },
    {
        "id": "TC-002",
        "title": "Login fails with incorrect password",
        "steps": [
            "Navigate to /login",
            "Enter email: user@example.com",
            "Enter password: wrongpassword",
            "Click Login"
        ],
        "expected": "Error message: 'Invalid email or password'",
        "type": "Negative/Functional"
    },
    {
        "id": "TC-003",
        "title": "Email field rejects invalid format",
        "steps": [
            "Navigate to /login",
            "Enter email: notanemail",
            "Enter any password",
            "Click Login"
        ],
        "expected": "Inline validation error: 'Please enter a valid email'",
        "type": "Boundary/Functional"
    },
    {
        "id": "TC-004",
        "title": "Empty fields show required validation",
        "steps": [
            "Navigate to /login",
            "Leave both fields empty",
            "Click Login"
        ],
        "expected": "Both fields highlight red with 'This field is required'",
        "type": "Boundary/Functional"
    },
    {
        "id": "TC-005",
        "title": "SQL injection in email field is rejected safely",
        "steps": [
            "Navigate to /login",
            "Enter email: ' OR 1=1; --",
            "Enter any password",
            "Click Login"
        ],
        "expected": "Login fails safely; no database error exposed",
        "type": "Security/Negative"
    },
]

for tc in login_test_cases:
    print(f"{tc['id']}: {tc['title']} [{tc['type']}]")
```

## Concept

<En>
**Phase 4 recap — the essential skills:**

| Skill | Key insight |
|-------|-------------|
| HTTP | Method + URL + headers + body → status + body + headers |
| REST | Stateless, resource URLs, HTTP verbs convey intent |
| Status codes | 2xx = success, 4xx = client error, 5xx = server error |
| Postman | Explore first, then automate — environments enable reuse |
| requests | Session for shared headers; json= serialises automatically |
| pytest + requests | ApiClient wraps Session; fixtures share setup |
| JSON Schema | validate() catches type/presence/range errors in one call |
| Negative testing | Missing fields, wrong types, BVA, security payloads |
| Mocking | responses library intercepts requests — test offline |
| API + UI hybrid | API setup is 50–100x faster than UI setup |
| CI | No browser install needed; --junit-xml for CI parsing |

**Idempotency — an important REST concept:**
An operation is idempotent if calling it multiple times has the same effect as calling it once. In REST:
- **Idempotent**: GET, PUT, DELETE, HEAD — calling them N times leaves the server in the same state as calling them once
- **Not idempotent**: POST — each call creates a new resource

This matters in tests: if your DELETE test fails halfway and you re-run it, the resource may already be gone. An idempotent DELETE handles "resource not found" gracefully.

**RESTful URL patterns:**
| RESTful | Not RESTful |
|---------|------------|
| `GET /users/42` | `GET /getUser?id=42` |
| `POST /users` | `POST /createUser` |
| `DELETE /users/42` | `POST /users/42/delete` |
| `PATCH /users/42` | `PUT /users/updatePartial` |

REST uses nouns for resources and HTTP methods to express the action — not verbs in the URL.

**The API testing checklist for any endpoint:**
- [ ] Status code is correct for the HTTP method and scenario
- [ ] Response body validates against the schema
- [ ] All required fields are present and non-null
- [ ] Field types are correct (int, str, bool, list, object)
- [ ] Business rules are satisfied (email format, valid roles, positive IDs)
- [ ] Error cases return 4xx with a meaningful message (not 500)
- [ ] Response time is within acceptable limits
- [ ] Sensitive data is not leaked in error responses

**The most commonly forgotten item by beginners:**
The last two — response time assertions and leak checks. Beginners focus on status codes and field presence, but a slow API and leaking stack traces are real production defects. Add at least one performance assertion and verify that 404 responses don't expose internal paths or framework names.

**Idempotency — một khái niệm REST quan trọng:**
Một thao tác là idempotent nếu gọi nó nhiều lần có cùng kết quả với gọi một lần. Trong REST:
- **Idempotent**: GET, PUT, DELETE, HEAD — gọi chúng N lần để server ở cùng trạng thái như gọi một lần
- **Không idempotent**: POST — mỗi lần gọi tạo một tài nguyên mới

Điều này quan trọng trong test: nếu test DELETE của bạn thất bại giữa chừng và bạn chạy lại, tài nguyên có thể đã bị xoá. DELETE idempotent xử lý "resource not found" một cách duyên dáng.

**Mẫu URL RESTful:**
| RESTful | Không RESTful |
|---------|------------|
| `GET /users/42` | `GET /getUser?id=42` |
| `POST /users` | `POST /createUser` |
| `DELETE /users/42` | `POST /users/42/delete` |
| `PATCH /users/42` | `PUT /users/updatePartial` |

REST dùng danh từ cho tài nguyên và HTTP method để diễn đạt hành động — không dùng động từ trong URL.

**Checklist kiểm thử API cho bất kỳ endpoint nào:**
- [ ] Status code đúng cho HTTP method và kịch bản
- [ ] Body response xác thực với schema
- [ ] Tất cả trường bắt buộc có mặt và không null
- [ ] Kiểu trường đúng (int, str, bool, list, object)
- [ ] Quy tắc nghiệp vụ được đáp ứng (định dạng email, role hợp lệ, ID dương)
- [ ] Trường hợp lỗi trả về 4xx với thông báo có ý nghĩa (không phải 500)
- [ ] Thời gian response trong giới hạn chấp nhận được
- [ ] Dữ liệu nhạy cảm không bị rò rỉ trong error response

**Mục thường bị bỏ sót nhất bởi người mới:**
Hai mục cuối — assertion thời gian response và kiểm tra rò rỉ. Người mới tập trung vào status code và sự hiện diện của trường, nhưng API chậm và rò rỉ stack trace là các lỗi production thực sự. Thêm ít nhất một assertion hiệu suất và xác minh rằng response 404 không lộ đường dẫn nội bộ hoặc tên framework.

# A complete, well-structured API test demonstrating all Phase 4 patterns

import pytest
import requests
import time
from jsonschema import validate, ValidationError

BASE_URL = "https://jsonplaceholder.typicode.com"

# Schema — defined once, reused across tests
COMMENT_SCHEMA = {
    "type": "object",
    "required": ["id", "postId", "name", "email", "body"],
    "properties": {
        "id":     {"type": "integer", "minimum": 1},
        "postId": {"type": "integer", "minimum": 1},
        "name":   {"type": "string",  "minLength": 1},
        "email":  {"type": "string"},
        "body":   {"type": "string",  "minLength": 1},
    },
}

@pytest.fixture(scope="session")
def session() -> requests.Session:
    s = requests.Session()
    s.headers["Content-Type"] = "application/json"
    return s

# Happy path + schema validation
def test_get_comment_by_id(session: requests.Session):
    response = session.get(f"{BASE_URL}/comments/1")
    assert response.status_code == 200
    validate(instance=response.json(), schema=COMMENT_SCHEMA)

# Parametrized positive test
@pytest.mark.parametrize("post_id,expected_count", [
    (1, 5),
    (2, 5),
])
def test_comments_per_post(session: requests.Session, post_id: int, expected_count: int):
    response = session.get(f"{BASE_URL}/posts/{post_id}/comments")
    assert response.status_code == 200
    comments = response.json()
    assert len(comments) == expected_count
    for comment in comments:
        assert comment["postId"] == post_id
        validate(instance=comment, schema=COMMENT_SCHEMA)

# Negative test
def test_comment_not_found(session: requests.Session):
    response = session.get(f"{BASE_URL}/comments/99999")
    assert response.status_code == 404

# Performance assertion
def test_response_time(session: requests.Session):
    start = time.time()
    session.get(f"{BASE_URL}/comments/1")
    assert time.time() - start < 3.0, "Response too slow"

# Business rule — every comment has a valid email-ish field
def test_all_comments_have_email(session: requests.Session):
    response = session.get(f"{BASE_URL}/comments", params={"_limit": 10})
    assert response.status_code == 200
    for comment in response.json():
        assert "@" in comment["email"], f"Invalid email: {comment['email']}"
```

# Pattern gallery — all Phase 4 techniques in one place for quick reference

import requests
import responses
import pytest
from jsonschema import validate

# 1. ApiClient with Session (Day 47)
class ApiClient:
    BASE_URL = "https://jsonplaceholder.typicode.com"
    def __init__(self):
        self.session = requests.Session()
        self.session.headers["Content-Type"] = "application/json"
    def get(self, path, **kw): return self.session.get(f"{self.BASE_URL}{path}", **kw)
    def post(self, path, **kw): return self.session.post(f"{self.BASE_URL}{path}", **kw)

# 2. Schema validation (Day 44)
ALBUM_SCHEMA = {
    "type": "object",
    "required": ["id", "userId", "title"],
    "properties": {
        "id":     {"type": "integer", "minimum": 1},
        "userId": {"type": "integer", "minimum": 1},
        "title":  {"type": "string",  "minLength": 1},
    },
}

# 3. Session fixture (Day 47)
@pytest.fixture(scope="session")
def api(): return ApiClient()

# 4. Happy path + schema
def test_get_album(api):
    r = api.get("/albums/1")
    assert r.status_code == 200
    validate(instance=r.json(), schema=ALBUM_SCHEMA)

# 5. Negative test
def test_album_not_found(api):
    r = api.get("/albums/99999")
    assert r.status_code == 404

# 6. Parametrize
@pytest.mark.parametrize("album_id", [1, 50, 100])
def test_albums_parametrized(api, album_id):
    r = api.get(f"/albums/{album_id}")
    assert r.status_code == 200
    assert r.json()["id"] == album_id

# 7. Mock (Day 45)
@responses.activate
def test_album_mocked():
    responses.add(responses.GET, "https://jsonplaceholder.typicode.com/albums/1",
                  json={"id": 1, "userId": 1, "title": "Mock Album"}, status=200)
    r = requests.get("https://jsonplaceholder.typicode.com/albums/1")
    assert r.status_code == 200
    assert r.json()["title"] == "Mock Album"

# 8. POST + 201
def test_create_album(api):
    r = api.post("/albums", json={"title": "Review Album", "userId": 1})
    assert r.status_code == 201
    assert "id" in r.json()
```

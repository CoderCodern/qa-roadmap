## Intro

<En>
Before automating API tests in Python, you need to understand and manually explore the API. Postman is the industry-standard GUI tool for this. It lets you send requests, inspect responses, and build collections of tests — all without writing a single line of code. It's also a great tool for understanding an unfamiliar API before automating it.
</En>
<Vi>
Trước khi tự động hoá API test trong Python, bạn cần hiểu và khám phá API thủ công. Postman là công cụ GUI tiêu chuẩn công nghiệp cho điều này. Nó cho phép bạn gửi request, kiểm tra response và xây dựng collection test — tất cả mà không cần viết một dòng code nào. Đây cũng là công cụ tuyệt vời để hiểu API chưa quen trước khi tự động hoá nó.
</Vi>

## Concept

<En>
**Key Postman concepts:**

| Concept | Description |
|---------|-------------|
| **Request** | One HTTP call (method + URL + headers + body) |
| **Collection** | A group of related requests that can be run together or shared with the team |
| **Environment** | A set of key-value variables (base URL, API key, tokens) scoped to a deployment context |
| **Variable** | `{{base_url}}` — a named placeholder replaced at runtime with the current environment value |
| **Test script** | JavaScript that runs *after* the response arrives — used to write assertions |
| **Pre-request script** | JavaScript that runs *before* the request is sent — used to generate dynamic data or set variables |
| **Runner** | Postman's built-in tool to execute an entire collection in sequence |

**Postman test scripts (JavaScript):**

Test scripts live in the **Tests** tab of any request. They run automatically after the response is received and appear in the **Test Results** panel.

```javascript
pm.test("Status is 200", () => {
    pm.response.to.have.status(200);
});

pm.test("Response has id field", () => {
    const body = pm.response.json();
    pm.expect(body).to.have.property("id");
    pm.expect(body.id).to.be.a("number");
});

// Save to environment for use in next request
pm.environment.set("user_id", pm.response.json().id);
```

**The Postman assertion API — most used methods:**

| Method | What it asserts |
|--------|----------------|
| `pm.response.to.have.status(200)` | Exact status code match |
| `pm.expect(body).to.have.property("id")` | Key exists in object |
| `pm.expect(body.name).to.be.a("string")` | Type check (string, number, boolean, object, array) |
| `pm.expect(body.id).to.equal(42)` | Exact value match |
| `pm.expect(body.items).to.be.an("array")` | Type check for array |
| `pm.expect(body.items).to.have.lengthOf(10)` | Array length check |
| `pm.expect(pm.response.responseTime).to.be.below(2000)` | Performance check |
| `pm.expect(body.email).to.include("@")` | Substring check |

**Postman environments — how they work:**

An environment is a named set of key-value pairs. You switch between environments to run the same collection against different servers without changing any request.

Example environment: **Staging**
```
base_url = https://staging.example.com
api_key  = staging-key-abc123
user_id  = (empty — set by a test script after login)
```

Example environment: **Production**
```
base_url = https://api.example.com
api_key  = prod-key-xyz789
user_id  = (empty)
```

Every `{{base_url}}` in your requests resolves to the active environment's value automatically.

**Request chaining with environment variables:**

A powerful Postman workflow is to chain requests: request A creates a resource and saves its `id` to the environment, then request B uses `{{resource_id}}` as part of its URL.

```
Request A: POST /users        → pm.environment.set("user_id", body.id)
Request B: GET  /users/{{user_id}}  → uses the saved id automatically
Request C: DELETE /users/{{user_id}}
```

**Pre-request scripts — when and why:**

Pre-request scripts run before the request is sent. Common uses:
- Generate a timestamp or random value: `pm.environment.set("timestamp", Date.now())`
- Compute an HMAC signature for auth
- Set up test data values before creating a resource

**pm.test() behaviour on failure:**

When a `pm.test()` assertion fails, it marks that test as failed in the results panel but *continues running the remaining tests in the script*. It does not stop the entire collection. To stop a collection run on failure, use the Collection Runner's stop-on-error option or a `postman.setNextRequest(null)` call.

**Why use Postman even if you automate in Python:**
- Fastest way to explore an unfamiliar API before writing code
- Share collections with team members who do not write code
- Run collections in CI via Newman (Day 41)
- Visual response inspection catches issues faster than reading raw JSON strings
- Mock servers let you test against an API that is not built yet
</En>
<Vi>
**Các khái niệm Postman quan trọng:**

| Khái niệm | Mô tả |
|-----------|-------|
| **Request** | Một cuộc gọi HTTP (method + URL + headers + body) |
| **Collection** | Nhóm các request liên quan có thể chạy cùng nhau hoặc chia sẻ với nhóm |
| **Environment** | Tập biến key-value (base URL, API key, token) cho một ngữ cảnh triển khai |
| **Variable** | `{{base_url}}` — placeholder được thay thế lúc runtime bằng giá trị environment hiện tại |
| **Test script** | JavaScript chạy *sau* khi response đến — dùng để viết assertion |
| **Pre-request script** | JavaScript chạy *trước* khi request được gửi — dùng để tạo dữ liệu động hoặc đặt biến |
| **Runner** | Công cụ tích hợp của Postman để chạy toàn bộ collection theo thứ tự |

**Test script Postman (JavaScript):**

Test script nằm trong tab **Tests** của bất kỳ request nào. Chúng chạy tự động sau khi response được nhận và hiện trong panel **Test Results**.

```javascript
pm.test("Status is 200", () => {
    pm.response.to.have.status(200);
});

pm.test("Response has id field", () => {
    const body = pm.response.json();
    pm.expect(body).to.have.property("id");
    pm.expect(body.id).to.be.a("number");
});

// Lưu vào environment cho request tiếp theo
pm.environment.set("user_id", pm.response.json().id);
```

**API assertion Postman — các method hay dùng nhất:**

| Method | Assert gì |
|--------|----------|
| `pm.response.to.have.status(200)` | Khớp chính xác status code |
| `pm.expect(body).to.have.property("id")` | Key tồn tại trong object |
| `pm.expect(body.name).to.be.a("string")` | Kiểm tra kiểu (string, number, boolean, object, array) |
| `pm.expect(body.id).to.equal(42)` | Khớp giá trị chính xác |
| `pm.expect(body.items).to.be.an("array")` | Kiểm tra kiểu array |
| `pm.expect(body.items).to.have.lengthOf(10)` | Kiểm tra độ dài array |
| `pm.expect(pm.response.responseTime).to.be.below(2000)` | Kiểm tra hiệu năng |
| `pm.expect(body.email).to.include("@")` | Kiểm tra chuỗi con |

**Postman environment — cách hoạt động:**

Environment là tập hợp có tên của các cặp key-value. Bạn chuyển đổi giữa các environment để chạy cùng một collection trên các server khác nhau mà không thay đổi bất kỳ request nào.

Ví dụ environment: **Staging**
```
base_url = https://staging.example.com
api_key  = staging-key-abc123
user_id  = (rỗng — được đặt bởi test script sau khi đăng nhập)
```

Mỗi `{{base_url}}` trong request tự động resolve thành giá trị environment đang hoạt động.

**Chaining request với biến environment:**

Workflow Postman mạnh mẽ là chaining request: request A tạo tài nguyên và lưu `id` vào environment, rồi request B dùng `{{resource_id}}` trong URL.

```
Request A: POST /users        → pm.environment.set("user_id", body.id)
Request B: GET  /users/{{user_id}}  → tự động dùng id đã lưu
Request C: DELETE /users/{{user_id}}
```

**pm.test() khi thất bại:**

Khi assertion `pm.test()` thất bại, nó đánh dấu test đó là failed trong panel kết quả nhưng *tiếp tục chạy các test còn lại trong script*. Nó không dừng toàn bộ collection.

**Tại sao dùng Postman ngay cả khi tự động hoá bằng Python:**
- Cách nhanh nhất để khám phá API chưa quen trước khi viết code
- Chia sẻ collection với thành viên không viết code
- Chạy collection trong CI qua Newman (Ngày 41)
- Kiểm tra response trực quan phát hiện vấn đề nhanh hơn đọc JSON thô
</Vi>

<En>

**Part 1 — Testing a GET request in Postman**

Open Postman, create a new request with `GET https://jsonplaceholder.typicode.com/posts/1`, paste the script below into the **Tests** tab, then click Send.

</En>
<Vi>

**Phần 1 — Kiểm thử GET request trong Postman**

Mở Postman, tạo request mới với `GET https://jsonplaceholder.typicode.com/posts/1`, dán script dưới đây vào tab **Tests**, rồi nhấn Send.

</Vi>

```javascript
// Postman Tests tab — GET /posts/1

pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response time is acceptable", function () {
    pm.expect(pm.response.responseTime).to.be.below(2000);
});

pm.test("Response has required fields", function () {
    const post = pm.response.json();
    pm.expect(post).to.have.property("id");
    pm.expect(post).to.have.property("title");
    pm.expect(post).to.have.property("body");
    pm.expect(post).to.have.property("userId");
});

pm.test("Field types are correct", function () {
    const post = pm.response.json();
    pm.expect(post.id).to.be.a("number");
    pm.expect(post.title).to.be.a("string");
    pm.expect(post.title.length).to.be.above(0);
    pm.expect(post.userId).to.be.a("number");
});

// Save the post id for use in subsequent requests in the collection
pm.environment.set("post_id", pm.response.json().id);
```

**Phần 2 — Kiểm thử POST request và chaining với biến environment**

Tạo request thứ hai: `POST https://jsonplaceholder.typicode.com/posts` với body `{"title": "My Test Post", "body": "Test content", "userId": 1}`. Dán script sau vào tab **Tests** của nó.

```javascript
pm.test("Status code is 201", function () {

    const newPost = pm.response.json();

    pm.expect(newPost.id).to.be.a("number");
    pm.expect(newPost.id).to.be.above(0);

    const newPost = pm.response.json();
    pm.expect(newPost).to.have.property("userId");
```

**Phần 3 — Dùng environment và pre-request script**

Tạo Postman environment tên **JSONPlaceholder**. Thêm biến `base_url = https://jsonplaceholder.typicode.com`. Cập nhật request để dùng `{{base_url}}/posts`. Sau đó dùng pre-request script này để tạo tiêu đề duy nhất trước mỗi POST.

```javascript
// Postman Pre-request Script tab — runs BEFORE the request is sent

// Generate a unique title using a timestamp so each test run creates a different post
const timestamp = Date.now();
pm.environment.set("post_title", `Test Post ${timestamp}`);

// Log so you can see it in the Postman Console (View → Show Postman Console)
console.log("Generated post title:", pm.environment.get("post_title"));

// Now reference {{post_title}} in the request body:
// {
//   "title": "{{post_title}}",
//   "body": "Content generated at runtime",
//   "userId": 1
// }
```

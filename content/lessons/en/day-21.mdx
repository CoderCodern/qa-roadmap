## Concept

<En>
**Project structure:**
```
calculator/
├── calculator.py       # core logic module
├── cli.py              # command-line interface
└── tests/
    ├── __init__.py
    └── test_calculator.py  # pytest test file
```

**pytest basics:**
- Any file named `test_*.py` or `*_test.py` is discovered automatically.
- Any function named `test_*` is a test.
- Use `assert` for assertions — pytest rewrites them for readable failure output.
- Run all tests: `pytest tests/`
- Run with verbose output: `pytest -v`
- Run a single test: `pytest tests/test_calculator.py::test_add`

**What makes a good pytest test:**
- Clear name describing what's being tested (`test_divide_raises_on_zero`)
- AAA pattern: Arrange, Act, Assert
- One logical concept per test
- `pytest.raises(ExceptionType)` to assert that an exception is raised

**Installing pytest:**
```bash
pip install pytest
```
</En>
<Vi>
**Cấu trúc dự án:**
```
calculator/
├── calculator.py       # module logic cốt lõi
├── cli.py              # giao diện dòng lệnh
└── tests/
    ├── __init__.py
    └── test_calculator.py  # file test pytest
```

**Cơ bản về pytest:**
- Bất kỳ file nào có tên `test_*.py` hoặc `*_test.py` đều được tự động phát hiện.
- Bất kỳ hàm nào có tên `test_*` đều là một test.
- Dùng `assert` cho assertion — pytest viết lại chúng cho đầu ra lỗi dễ đọc.
- Chạy tất cả test: `pytest tests/`
- Chạy với đầu ra chi tiết: `pytest -v`

**Cài đặt pytest:**
```bash
pip install pytest
```
</Vi>

## Code / Demo

**Pattern 1 — Core arithmetic functions**

> 📄 File: `calculator/calculator.py`

<En>Start with the simplest pieces first. Each function does exactly one thing and is independently testable. The AAA pattern (Arrange, Act, Assert) keeps each verification clear — even without pytest.</En>
<Vi>Bắt đầu với các phần đơn giản nhất trước. Mỗi hàm làm đúng một việc và có thể kiểm tra độc lập. Mẫu AAA (Arrange, Act, Assert) giữ cho mỗi xác minh rõ ràng — ngay cả khi không có pytest.</Vi>

<CodePlayground code={`
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

def multiply(a, b):
    return a * b

# Arrange → Act → Assert (AAA pattern)
assert add(2, 3)        == 5
assert add(-1, -4)      == -5
assert add(0, 0)        == 0

assert subtract(10, 4)  == 6
assert subtract(3, 10)  == -7

**Pattern 2 — `divide` with exception handling**

> 📄 File: `calculator/calculator.py` — add below Pattern 1 in the same file

<En>Division by zero is a domain-specific error. A custom `CalculatorError` lets callers catch it precisely without accidentally swallowing unrelated exceptions. Test both the happy path and the error path.</En>
<Vi>Chia cho zero là lỗi đặc thù của miền. `CalculatorError` tuỳ chỉnh cho phép người gọi bắt đúng lỗi đó mà không vô tình bắt các ngoại lệ không liên quan. Kiểm tra cả đường thành công lẫn đường lỗi.</Vi>

<CodePlayground code={`
class CalculatorError(Exception):
    pass

def divide(a, b):
    if b == 0:
        raise CalculatorError("Division by zero is not allowed")
    return a / b

# Happy path
assert divide(10, 2)  == 5.0
assert divide(9, 3)   == 3.0
assert divide(-6, 2)  == -3.0

# Error path — must raise CalculatorError when b is zero
try:
    divide(10, 0)
    print("ERROR: should have raised!")
except CalculatorError as e:
    print(f"Caught expected error: {e}")

# CalculatorError is specific — it does NOT catch other exceptions
try:
    divide("ten", 2)   # raises TypeError, not CalculatorError
except CalculatorError:
    print("ERROR: wrong exception type caught")
except TypeError as e:
    print(f"Correctly NOT caught by CalculatorError: {e}")

print("divide — all assertions passed!")
`} />

**Pattern 3 — `calculate()` dispatcher with dict-based dispatch**

> 📄 File: `calculator/calculator.py` — this completes the module; Patterns 1–3 together form the full file

<En>Instead of a long `if/elif` chain, map operator strings to functions in a dict. This makes adding new operations trivial — just add one entry. The unknown-operation check becomes a single `in` test.</En>
<Vi>Thay vì chuỗi `if/elif` dài, ánh xạ chuỗi toán tử sang hàm trong một dict. Điều này làm việc thêm phép tính mới trở nên đơn giản — chỉ cần thêm một entry. Kiểm tra phép tính không xác định trở thành một lần kiểm tra `in`.</Vi>

<CodePlayground code={`
class CalculatorError(Exception):
    pass

def add(a, b):      return a + b
def subtract(a, b): return a - b
def multiply(a, b): return a * b
def divide(a, b):
    if b == 0:
        raise CalculatorError("Division by zero is not allowed")
    return a / b

def calculate(operation, a, b):
    ops = {"+": add, "-": subtract, "*": multiply, "/": divide}
    if operation not in ops:
        raise CalculatorError(f"Unknown operation: '{operation}'")
    return ops[operation](a, b)

# Happy path — all four operations
assert calculate("+", 3, 4)  == 7
assert calculate("-", 10, 3) == 7
assert calculate("*", 6, 7)  == 42
assert calculate("/", 9, 3)  == 3.0

# Error paths
try:
    calculate("^", 2, 3)
    print("ERROR: should have raised!")
except CalculatorError as e:
    print(f"Unknown op caught: {e}")

try:
    calculate("/", 5, 0)
    print("ERROR: should have raised!")
except CalculatorError as e:
    print(f"Divide-by-zero caught: {e}")

print("calculate — all assertions passed!")
`} />

**Pattern 4 — Writing tests the pytest way (AAA + parametrised cases)**

> 📄 File: `calculator/tests/test_calculator.py` — this is a separate file from the logic; run it with `pytest tests/`

<En>In real pytest files each test is a separate `test_` function. Running the same logic against multiple inputs is done by looping over a list of `(inputs, expected)` tuples — the precursor to pytest's `@pytest.mark.parametrize`. Failures are collected and reported all at once.</En>
<Vi>Trong file pytest thực tế mỗi test là một hàm `test_` riêng biệt. Chạy cùng logic với nhiều đầu vào được thực hiện bằng cách lặp qua danh sách các tuple `(đầu vào, mong đợi)` — tiền thân của `@pytest.mark.parametrize` của pytest. Lỗi được thu thập và báo cáo cùng lúc.</Vi>

<CodePlayground code={`
class CalculatorError(Exception):
    pass

def add(a, b):      return a + b
def subtract(a, b): return a - b
def multiply(a, b): return a * b
def divide(a, b):
    if b == 0: raise CalculatorError("Division by zero is not allowed")
    return a / b

def calculate(op, a, b):
    ops = {"+": add, "-": subtract, "*": multiply, "/": divide}
    if op not in ops: raise CalculatorError(f"Unknown operation: '{op}'")
    return ops[op](a, b)

# Parametrised test cases — (operation, a, b, expected)
test_cases = [
    ("+",  2,   3,   5),
    ("+",  -1,  -4,  -5),
    ("-",  10,  4,   6),
    ("-",  3,   10,  -7),
    ("*",  6,   7,   42),
    ("*",  100, 0,   0),
    ("/",  10,  2,   5.0),
    ("/",  9,   3,   3.0),
]

failures = []
for op, a, b, expected in test_cases:
    result = calculate(op, a, b)
    if result != expected:
        failures.append(f"calculate({op!r}, {a}, {b}) → {result}, expected {expected}")

assert not failures, "\\n".join(failures)
print(f"All {len(test_cases)} parametrised cases passed!")

# Test that errors are raised correctly
error_cases = [("/", 5, 0), ("^", 2, 3)]
for op, a, b in error_cases:
    try:
        calculate(op, a, b)
        failures.append(f"calculate({op!r}, {a}, {b}) should have raised")
    except CalculatorError:
        pass   # expected

assert not failures
print("All error-path cases raised CalculatorError correctly!")
`} />

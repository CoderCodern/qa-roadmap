## Concept

<En>
**Phase 3 recap — the essential skills:**

| Skill | Key insight |
|-------|-------------|
| Browser automation | Playwright launches a real browser; it's not mocking |
| Locators | Role-based > label-based > placeholder > text > testid > CSS > XPath |
| Auto-wait | Playwright checks 5 actionability conditions before every action |
| Assertions | `expect()` retries; `assert` is one-shot — use the right tool |
| Screenshots | Debug tool and visual regression baseline |
| POM | Encapsulate locators in classes; tests call methods, not locators |
| Fixtures | `yield` = setup before / teardown after |
| parametrize | One test function, many inputs; avoids duplication |
| CI | `.github/workflows/*.yml`; always upload artifacts on failure |

**Common mistakes to avoid going forward:**
- Mixing locators into test functions (use POM)
- Using `time.sleep()` instead of `expect()` waits
- Ignoring browser console errors (add a console listener)
- Writing tests that depend on execution order (each test must be independent)
- Not cleaning up after tests (each test should leave no trace for the next)
</En>
<Vi>
**Tóm tắt Phase 3 — các kỹ năng thiết yếu:**

| Kỹ năng | Điểm mấu chốt |
|-------|-------------|
| Tự động hoá trình duyệt | Playwright khởi chạy trình duyệt thực; không phải mock |
| Locator | Role-based > label-based > placeholder > text > testid > CSS > XPath |
| Auto-wait | Playwright kiểm tra 5 điều kiện hành động trước mỗi action |
| Assertion | `expect()` thử lại; `assert` là một lần — dùng đúng công cụ |
| Ảnh chụp màn hình | Công cụ gỡ lỗi và baseline hồi quy trực quan |
| POM | Đóng gói locator trong class; test gọi method, không phải locator |
| Fixture | `yield` = setup trước / teardown sau |
| parametrize | Một hàm test, nhiều đầu vào |
| CI | `.github/workflows/*.yml`; luôn tải artifact khi thất bại |

**Các lỗi phổ biến cần tránh:**
- Trộn locator vào hàm test (dùng POM)
- Dùng `time.sleep()` thay vì `expect()` wait
- Bỏ qua lỗi console trình duyệt
- Viết test phụ thuộc vào thứ tự thực thi
</Vi>

## Code / Demo

```python
# A complete, well-structured Playwright test — demonstrating all Phase 3 skills

import pytest
from playwright.sync_api import Page, expect
from pages.todo_page import TodoPage  # POM import

# Fixture — setup and teardown
@pytest.fixture
def fresh_todo(page: Page) -> TodoPage:
    todo = TodoPage(page)
    todo.navigate()
    yield todo
    # Teardown: nothing to clean — fresh browser context per test

# Parametrize — data-driven testing
@pytest.mark.parametrize("items,expected_count", [
    (["Task 1"], 1),
    (["Task A", "Task B", "Task C"], 3),
])
def test_add_items_count(fresh_todo: TodoPage, items: list, expected_count: int):
    for item in items:
        fresh_todo.add(item)
    assert fresh_todo.get_count() == expected_count

# Clear assertion — uses expect() for auto-retry
def test_item_visible_after_add(fresh_todo: TodoPage):
    fresh_todo.add("Automation is fun")
    # expect() auto-retries until visible or timeout
    expect(fresh_todo.page.get_by_role("listitem")).to_contain_text("Automation is fun")

# Negative test — verifying something does NOT happen
def test_empty_submit_does_not_add(fresh_todo: TodoPage):
    fresh_todo.new_todo_input.press("Enter")
    assert fresh_todo.get_count() == 0

# Screenshot on key step
def test_complete_flow_with_screenshot(fresh_todo: TodoPage, tmp_path):
    fresh_todo.add("Review Phase 3")
    fresh_todo.page.screenshot(path=str(tmp_path / "before_complete.png"))
    fresh_todo.complete("Review Phase 3")
    fresh_todo.page.screenshot(path=str(tmp_path / "after_complete.png"))
    completed = fresh_todo.page.locator(".todo-list li.completed")
    assert completed.count() == 1
```

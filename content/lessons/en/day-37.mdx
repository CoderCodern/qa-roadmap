## Intro

<En>
REST is the architectural style used by the vast majority of web APIs you will test. JSON is the data format those APIs exchange. Understanding REST constraints and JSON structure is not optional — it's the foundation for every assertion you'll write in Phase 4. By the end of today you can look at any REST API response and immediately know what to test.
</En>
<Vi>
REST là kiến trúc được sử dụng bởi phần lớn các web API bạn sẽ kiểm thử. JSON là định dạng dữ liệu mà những API đó trao đổi. Hiểu các ràng buộc REST và cấu trúc JSON không phải là tùy chọn — đó là nền tảng cho mọi assertion bạn sẽ viết trong Phase 4. Cuối ngày, bạn có thể nhìn vào bất kỳ API response REST nào và ngay lập tức biết phải kiểm thử gì.
</Vi>

## Concept

<En>
**The six REST constraints:**

REST (Representational State Transfer) is not a protocol — it is a set of architectural constraints. An API that satisfies them is called RESTful.

| Constraint | What it means in practice |
|------------|--------------------------|
| **Stateless** | Each request carries all information needed. The server keeps no session state between requests. Auth token must be in every request. |
| **Client-server** | The UI and backend are independent. Either can change without breaking the other, as long as the interface contract is stable. |
| **Resource-based** | URLs identify resources, not actions. `/users/42` is a resource. `/getUser?id=42` is not RESTful — it puts the verb in the URL. |
| **HTTP verbs convey intent** | GET reads, POST creates, PUT replaces, PATCH partially updates, DELETE removes. The method is the action. |
| **Uniform interface** | Consistent response structure across all endpoints. If `/users` returns `{"items": [], "total": 0}`, so should `/products`. |
| **Cacheable** | Responses should indicate whether they can be cached. GET responses are typically cacheable; POST is not. |

**Why stateless matters for testing:**

Because no session state is stored server-side, you can run tests in any order, in parallel, and against any server instance. A stateful API requires tests to run in sequence and share cookies/sessions — making tests fragile and hard to scale.

**RESTful URL conventions:**

```
GET    /users            → list all users (collection)
POST   /users            → create a new user
GET    /users/42         → get a specific user
PUT    /users/42         → replace user 42 entirely
PATCH  /users/42         → update specific fields of user 42
DELETE /users/42         → delete user 42
GET    /users/42/posts   → list posts belonging to user 42
POST   /users/42/posts   → create a post for user 42
```

Non-RESTful URLs to flag during API review:

| Bad URL | Why it is wrong | RESTful alternative |
|---------|----------------|---------------------|
| `/getUser?id=42` | Verb in URL | `GET /users/42` |
| `/createOrder` | Verb in URL | `POST /orders` |
| `/users/delete/42` | Verb in URL | `DELETE /users/42` |
| `/users/42/activate` | Action on resource is OK if truly an action | Acceptable — `/activate` is an action, not a resource |

**JSON data types — every type and its Python equivalent:**

| JSON type | Example | Python equivalent | isinstance() check |
|-----------|---------|-------------------|-------------------|
| string | `"hello"` | `str` | `isinstance(v, str)` |
| number (int) | `42` | `int` | `isinstance(v, int)` |
| number (float) | `3.14` | `float` | `isinstance(v, float)` |
| boolean | `true` / `false` | `bool` | `isinstance(v, bool)` |
| null | `null` | `None` | `v is None` |
| array | `[1, 2, 3]` | `list` | `isinstance(v, list)` |
| object | `{"key": "val"}` | `dict` | `isinstance(v, dict)` |

**Python gotcha:** In Python, `bool` is a subclass of `int`. This means `isinstance(True, int)` returns `True`. Always check `isinstance(v, bool)` before checking `isinstance(v, int)` when distinguishing them:

```python
# Wrong order — True passes the int check before bool check
value = True
if isinstance(value, int):
    print("int")   # This prints for True too!

# Correct order
if isinstance(value, bool):
    print("bool")
elif isinstance(value, int):
    print("int")
```

**What to test in a REST response — full checklist:**

| Category | What to assert |
|----------|----------------|
| Status code | Matches the expected code for the method and action |
| Required fields | All documented fields are present (`"id" in body`) |
| Field types | Each field has the correct type (`isinstance`) |
| Non-null guarantees | Required fields are not `None` |
| ID assignment | Created resources have a positive integer `id` |
| Timestamps | Present and in ISO 8601 UTC format (`"T"` and `"Z"` present) |
| Nested objects | Sub-objects are dicts with their own required fields |
| Arrays | List fields contain the right element type |
| Pagination | `total`, `page`, `limit` present and logically consistent |
| Enum fields | Role/status fields only contain allowed values |
</En>
<Vi>
**Sáu ràng buộc REST:**

REST (Representational State Transfer) không phải là giao thức — đó là một tập hợp ràng buộc kiến trúc. API thỏa mãn chúng được gọi là RESTful.

| Ràng buộc | Ý nghĩa trong thực tế |
|-----------|----------------------|
| **Stateless** | Mỗi request mang tất cả thông tin cần thiết. Server không lưu trạng thái phiên giữa các request. Token xác thực phải có trong mỗi request. |
| **Client-server** | UI và backend độc lập. Cái này có thể thay đổi mà không phá vỡ cái kia, miễn là hợp đồng giao diện ổn định. |
| **Resource-based** | URL xác định tài nguyên, không phải hành động. `/users/42` là tài nguyên. `/getUser?id=42` không phải RESTful — nó đặt động từ vào URL. |
| **HTTP verb truyền đạt ý định** | GET đọc, POST tạo, PUT thay thế, PATCH cập nhật một phần, DELETE xoá. Method chính là hành động. |
| **Giao diện thống nhất** | Cấu trúc response nhất quán trên tất cả endpoint. Nếu `/users` trả về `{"items": [], "total": 0}`, thì `/products` cũng vậy. |
| **Cacheable** | Response nên chỉ ra liệu chúng có thể được cache không. Response GET thường có thể cache; POST thì không. |

**Tại sao stateless quan trọng cho kiểm thử:**

Vì không có trạng thái phiên được lưu phía server, bạn có thể chạy test theo bất kỳ thứ tự nào, song song, và trên bất kỳ server instance nào. API stateful yêu cầu test chạy theo thứ tự và chia sẻ cookie/session — làm test dễ vỡ và khó mở rộng.

**Quy ước URL RESTful:**

```
GET    /users            → liệt kê tất cả user (collection)
POST   /users            → tạo user mới
GET    /users/42         → lấy user cụ thể
PUT    /users/42         → thay thế toàn bộ user 42
PATCH  /users/42         → cập nhật các trường cụ thể của user 42
DELETE /users/42         → xoá user 42
GET    /users/42/posts   → liệt kê bài viết của user 42
POST   /users/42/posts   → tạo bài viết cho user 42
```

URL không RESTful cần gắn cờ khi review API:

| URL xấu | Tại sao sai | Thay thế RESTful |
|---------|------------|-----------------|
| `/getUser?id=42` | Động từ trong URL | `GET /users/42` |
| `/createOrder` | Động từ trong URL | `POST /orders` |
| `/users/delete/42` | Động từ trong URL | `DELETE /users/42` |

**Kiểu dữ liệu JSON — mọi kiểu và tương đương Python:**

| Kiểu JSON | Ví dụ | Tương đương Python | Kiểm tra isinstance() |
|-----------|-------|-------------------|----------------------|
| string | `"hello"` | `str` | `isinstance(v, str)` |
| number (int) | `42` | `int` | `isinstance(v, int)` |
| number (float) | `3.14` | `float` | `isinstance(v, float)` |
| boolean | `true` / `false` | `bool` | `isinstance(v, bool)` |
| null | `null` | `None` | `v is None` |
| array | `[1, 2, 3]` | `list` | `isinstance(v, list)` |
| object | `{"key": "val"}` | `dict` | `isinstance(v, dict)` |

**Chú ý Python:** `bool` là lớp con của `int`. `isinstance(True, int)` trả về `True`. Luôn kiểm tra `isinstance(v, bool)` trước `isinstance(v, int)`:

```python
# Thứ tự sai — True vượt qua kiểm tra int trước bool
value = True
if isinstance(value, int):
    print("int")   # In ra cả với True!

# Thứ tự đúng
if isinstance(value, bool):
    print("bool")
elif isinstance(value, int):
    print("int")
```

**Những gì cần kiểm thử trong REST response — danh sách đầy đủ:**

| Danh mục | Điều cần assert |
|----------|----------------|
| Status code | Khớp với code mong đợi cho method và hành động |
| Trường bắt buộc | Tất cả trường được ghi chép đều có mặt (`"id" in body`) |
| Kiểu trường | Mỗi trường có kiểu đúng (`isinstance`) |
| Đảm bảo không null | Các trường bắt buộc không phải `None` |
| Gán ID | Tài nguyên đã tạo có `id` là số nguyên dương |
| Timestamps | Có mặt và theo định dạng ISO 8601 UTC |
| Object lồng nhau | Sub-object là dict với các trường bắt buộc riêng |
| Mảng | Trường list chứa đúng kiểu phần tử |
| Phân trang | `total`, `page`, `limit` có mặt và nhất quán về mặt logic |
| Trường enum | Trường role/status chỉ chứa các giá trị được phép |

**Part 1 — Asserting fields, types, and values in a REST response**

</En>
<Vi>

**Phần 1 — Assert các trường, kiểu và giá trị trong REST response**

</Vi>

```python
import json

# A realistic REST API response for GET /users/42
raw_response = '''
{
  "id": 42,
  "email": "alice@example.com",
  "name": "Alice Smith",
  "role": "admin",
  "is_active": true,
  "created_at": "2024-01-15T09:30:00Z",
  "profile": {
    "avatar_url": "https://cdn.example.com/avatars/42.png",
    "bio": "Senior QA Engineer"
  },
  "tags": ["qa", "automation", "python"]
}
'''

user = json.loads(raw_response)

# --- Assert presence of required fields ---
required_fields = ["id", "email", "name", "role", "is_active", "created_at", "profile", "tags"]
for field in required_fields:
    assert field in user, f"Missing required field: {field}"

# --- Assert field types (note: check bool before int) ---
assert isinstance(user["id"], int),         f"id must be int, got {type(user['id'])}"
assert isinstance(user["email"], str),       "email must be str"
assert isinstance(user["name"], str),        "name must be str"
assert isinstance(user["is_active"], bool),  "is_active must be bool (not int)"
assert isinstance(user["tags"], list),       "tags must be a list"
assert isinstance(user["profile"], dict),    "profile must be a dict"

# --- Assert values ---
assert user["role"] in {"admin", "editor", "viewer"}, \
    f"Unexpected role: {user['role']}"
assert "@" in user["email"],  "email must contain @"
assert user["id"] > 0,        "id must be a positive integer"
assert user["name"].strip(),  "name must not be blank"

# --- Assert nested object fields ---
assert "avatar_url" in user["profile"], "profile must have avatar_url"
assert user["profile"]["avatar_url"].startswith("https://"), \
    "avatar_url must start with https://"

# --- Assert list contents ---
assert len(user["tags"]) > 0, "tags must not be empty"
for tag in user["tags"]:
    assert isinstance(tag, str), f"Each tag must be str, got {type(tag)}"

# --- Assert ISO 8601 timestamp format ---
created_at = user["created_at"]
assert "T" in created_at and "Z" in created_at, \
    "created_at should be ISO 8601 UTC format (contains T and Z)"

print("All REST response assertions passed!")
print(f"User: {user['name']} ({user['role']})")
```

**Part 2 — Asserting a paginated list response**

**Phần 2 — Assert response danh sách có phân trang**

```python
import json

# GET /users?page=2&limit=10
raw_list_response = '''
{
  "items": [
    {"id": 11, "email": "user11@example.com", "name": "User Eleven"},
    {"id": 12, "email": "user12@example.com", "name": "User Twelve"}
  ],
  "total": 47,
  "page": 2,
  "limit": 10
}
'''

data = json.loads(raw_list_response)

# --- Assert pagination envelope ---
assert "items" in data,  "Response must have items field"
assert "total" in data,  "Response must have total field"
assert "page"  in data,  "Response must have page field"
assert "limit" in data,  "Response must have limit field"

# --- Assert pagination types ---
assert isinstance(data["items"], list),  "items must be a list"
assert isinstance(data["total"], int),   "total must be int"
assert isinstance(data["page"],  int),   "page must be int"
assert isinstance(data["limit"], int),   "limit must be int"

# --- Assert pagination logic ---
assert data["total"] >= 0,     "total must be non-negative"
assert data["page"]  >= 1,     "page must be at least 1"
assert data["limit"] >= 1,     "limit must be at least 1"
assert len(data["items"]) <= data["limit"], \
    f"items count ({len(data['items'])}) must not exceed limit ({data['limit']})"

# --- Assert each item in the list ---
for item in data["items"]:
    assert isinstance(item, dict),       "Each item must be a dict"
    assert "id"    in item,              "Each item must have id"
    assert "email" in item,              "Each item must have email"
    assert isinstance(item["id"], int),  "item id must be int"
    assert "@" in item["email"],         "item email must contain @"

print(f"Paginated list valid: {len(data['items'])} items, page {data['page']}, total {data['total']}")
```

**Part 3 — Checking missing fields and null values safely**

</En>
<Vi>

**Phần 3 — Kiểm tra các trường bị thiếu và giá trị null một cách an toàn**

</Vi>

```python
import json

# A response where some optional fields are missing or null
partial_user_json = '''
{
  "id": 99,
  "email": "bob@example.com",
  "name": null,
  "role": "viewer",
  "is_active": true
}
'''

user = json.loads(partial_user_json)

# --- Check if a field is missing entirely ---
if "name" not in user:
    print("name field is missing from response")
else:
    # Field exists but may be null
    if user["name"] is None:
        print("name field is present but null — is this allowed by the spec?")
    else:
        assert isinstance(user["name"], str), "name must be str when present"

# --- Pattern: assert required, allow optional ---
REQUIRED = ["id", "email", "role", "is_active"]
OPTIONAL = ["name", "profile", "tags", "created_at"]

for field in REQUIRED:
    assert field in user and user[field] is not None, \
        f"Required field '{field}' is missing or null"

for field in OPTIONAL:
    if field in user and user[field] is not None:
        print(f"Optional field '{field}' is present: {user[field]}")

# --- JSON null vs Python None ---
# json.loads converts JSON null → Python None
assert user["name"] is None,         "JSON null becomes Python None"
assert not isinstance(user["name"], str), "null is not a string"

print("Null-safety checks passed!")
```

## Intro

<En>
Postman is great for manual exploration, but automated API tests run in Python. The `requests` library is Python's go-to HTTP client — simple, readable, and powerful. Every API testing framework you'll encounter (pytest + requests, API clients, SDK wrappers) uses `requests` under the hood. Today you make your first real HTTP calls from Python.
</En>
<Vi>
Postman rất tốt để khám phá thủ công, nhưng các API test tự động chạy trong Python. Thư viện `requests` là HTTP client hàng đầu của Python — đơn giản, dễ đọc và mạnh mẽ. Mọi framework kiểm thử API bạn sẽ gặp đều dùng `requests` bên dưới. Hôm nay bạn thực hiện các cuộc gọi HTTP thực sự đầu tiên từ Python.
</Vi>

## Concept

<En>
**Install:**
```bash
pip install requests
```

**Basic HTTP methods — same pattern for all:**
```python
import requests

response = requests.get("https://api.example.com/users")
response = requests.post("https://api.example.com/users", json={"email": "a@b.com"})
response = requests.put("https://api.example.com/users/1", json={"name": "Alice"})
response = requests.patch("https://api.example.com/users/1", json={"name": "Alice"})
response = requests.delete("https://api.example.com/users/1")
```

Every method returns the same `Response` object regardless of the HTTP verb. Learn the Response object well — it is the core of all API assertions.

**The Response object — your primary assertion surface:**

| Property/Method | What it gives you | Example value |
|-----------------|------------------|---------------|
| `response.status_code` | Integer HTTP status code | `200`, `404`, `201` |
| `response.json()` | Parse body as dict or list | `{"id": 1, "name": "Alice"}` |
| `response.text` | Body as a raw string | `'{"id":1}'` |
| `response.content` | Body as raw bytes | `b'{"id":1}'` |
| `response.headers` | Dict of response headers | `{"Content-Type": "application/json"}` |
| `response.ok` | `True` if status code < 400 | `True` |
| `response.raise_for_status()` | Raises `HTTPError` if status >= 400 | (raises or does nothing) |
| `response.elapsed` | Time the server took to respond | `datetime.timedelta(...)` |

**response.text vs response.json() — know the difference:**

- `response.text` always works — it returns whatever the server sent as a string. Useful when the server returns non-JSON (HTML errors, plain text).
- `response.json()` parses the string as JSON and returns a Python dict or list. Raises `json.JSONDecodeError` if the body is not valid JSON. Use this for all JSON APIs.

```python
# Prefer this:
data = response.json()  # dict — you can key into it directly
user_name = data["name"]

# Avoid this for structured data:
raw = response.text     # string — you'd have to parse it yourself
```

**Sending data — four common patterns:**

```python
# 1. JSON body (POST/PUT/PATCH) — sets Content-Type: application/json automatically
response = requests.post(url, json={"name": "Alice", "role": "admin"})

# 2. Query parameters (GET filtering/pagination) — handles encoding automatically
response = requests.get(url, params={"page": 2, "limit": 10, "q": "alice jones"})
# Produces: ?page=2&limit=10&q=alice+jones

# 3. Custom headers — auth, correlation ids, client version
response = requests.get(url, headers={
    "Authorization": "Bearer mytoken",
    "X-Request-Id": "test-run-001"
})

# 4. Form-encoded body — for legacy APIs or form submissions
response = requests.post(url, data={"username": "alice", "password": "secret"})
```

**raise_for_status() — the clean error pattern:**

```python
response = requests.get("https://api.example.com/users/99999")
response.raise_for_status()  # raises HTTPError if 4xx or 5xx — no if/else needed
user = response.json()
```

Without `raise_for_status()`, a 404 response does not raise an exception — `response.json()` still executes and may return an error payload that silently passes your assertions. Use `raise_for_status()` to fail loudly on any HTTP error.

**Timeouts — always set one:**

```python
# Without timeout: your test hangs forever if the server is down
response = requests.get(url, timeout=5)        # 5 seconds connect + read
response = requests.get(url, timeout=(3, 10))  # (connect_timeout, read_timeout)
```

Never make requests without a timeout in test code. A hanging test wastes CI minutes and blocks other jobs.

**Using a Session — recommended for test suites:**

```python
session = requests.Session()

# Set default headers for all requests made via this session
session.headers.update({
    "Authorization": "Bearer abc123",
    "Content-Type": "application/json",
    "X-Client-Version": "test-1.0"
})

# All requests share headers, cookies, and the underlying TCP connection pool
response = session.get("https://api.example.com/users")
response = session.post("https://api.example.com/posts", json={"title": "Test"})

# Sessions also persist cookies — useful when testing session-based auth
```

A `Session` reuses TCP connections (HTTP keep-alive), which makes test suites significantly faster than making a new connection per request. It also keeps a single place for shared auth headers — change the token in one spot, not 20 test functions.

**Các phương thức HTTP cơ bản — cùng pattern cho tất cả:**
```python
import requests

response = requests.get("https://api.example.com/users")
response = requests.post("https://api.example.com/users", json={"email": "a@b.com"})
response = requests.put("https://api.example.com/users/1", json={"name": "Alice"})
response = requests.patch("https://api.example.com/users/1", json={"name": "Alice"})
response = requests.delete("https://api.example.com/users/1")
```

Mọi phương thức đều trả về cùng một đối tượng `Response`. Hãy nắm vững đối tượng Response — đó là cốt lõi của tất cả các assertion API.

**Đối tượng Response — bề mặt assertion chính của bạn:**

| Thuộc tính/Phương thức | Cung cấp gì | Ví dụ giá trị |
|-----------------|------------------|---------------|
| `response.status_code` | Mã trạng thái HTTP số nguyên | `200`, `404`, `201` |
| `response.json()` | Phân tích body là dict hoặc list | `{"id": 1, "name": "Alice"}` |
| `response.text` | Body dạng chuỗi thô | `'{"id":1}'` |
| `response.content` | Body dạng bytes thô | `b'{"id":1}'` |
| `response.headers` | Dict header response | `{"Content-Type": "application/json"}` |
| `response.ok` | `True` nếu mã trạng thái < 400 | `True` |
| `response.raise_for_status()` | Raise `HTTPError` nếu status >= 400 | (raise hoặc không làm gì) |
| `response.elapsed` | Thời gian server phản hồi | `datetime.timedelta(...)` |

**response.text vs response.json() — biết sự khác biệt:**

- `response.text` luôn hoạt động — trả về bất kỳ thứ gì server gửi dưới dạng chuỗi. Hữu ích khi server trả về non-JSON.
- `response.json()` phân tích chuỗi dạng JSON và trả về dict hoặc list Python. Raise `json.JSONDecodeError` nếu body không phải JSON hợp lệ. Dùng cái này cho tất cả JSON API.

**Gửi dữ liệu — bốn pattern phổ biến:**

```python
# 1. JSON body — tự động đặt Content-Type: application/json
response = requests.post(url, json={"name": "Alice", "role": "admin"})

# 2. Query parameters — tự động xử lý encoding
response = requests.get(url, params={"page": 2, "limit": 10})

# 3. Header tùy chỉnh — auth, correlation id
response = requests.get(url, headers={"Authorization": "Bearer mytoken"})

# 4. Form-encoded body — cho API cũ hoặc form submission
response = requests.post(url, data={"username": "alice", "password": "secret"})
```

**raise_for_status() — pattern xử lý lỗi sạch:**

Không có `raise_for_status()`, response 404 không raise exception — `response.json()` vẫn thực thi và có thể trả về payload lỗi mà âm thầm vượt qua assertion. Dùng `raise_for_status()` để thất bại rõ ràng khi có lỗi HTTP.

**Timeout — luôn đặt:**

```python
response = requests.get(url, timeout=5)        # 5 giây connect + read
response = requests.get(url, timeout=(3, 10))  # (connect_timeout, read_timeout)
```

Không bao giờ tạo request không có timeout trong code test. Test treo làm mất phút CI và chặn các job khác.

**Dùng Session — khuyến nghị cho bộ test:**

```python
session = requests.Session()
session.headers.update({
    "Authorization": "Bearer abc123",
    "Content-Type": "application/json",
})
# Tất cả request dùng chung header, cookie và connection pool TCP
```

`Session` tái sử dụng kết nối TCP (HTTP keep-alive), giúp bộ test nhanh hơn đáng kể so với tạo kết nối mới cho mỗi request. Nó cũng giữ một nơi duy nhất cho auth header chung — thay đổi token ở một chỗ, không phải 20 hàm test.
</Vi>

# Real HTTP calls to JSONPlaceholder — a free, public REST API for testing
import requests

BASE_URL = "https://jsonplaceholder.typicode.com"

# --- GET a single resource and assert its shape ---
response = requests.get(f"{BASE_URL}/posts/1", timeout=10)
assert response.status_code == 200

# Assert types — a common source of subtle bugs

assert isinstance(post["title"], str)

assert response.status_code == 201

assert "id" in created
assert created["title"] == "My Test Post"
assert isinstance(created["id"], int)
print(f"Created post id: {created['id']}")

**Part 2 — Query params, raise_for_status, and DELETE**

</En>
<Vi>

**Phần 2 — Query params, raise_for_status và DELETE**

</Vi>

```python
# --- GET a list with query params ---
# params= automatically encodes the dict as ?userId=1&_limit=3
response = requests.get(
    f"{BASE_URL}/posts",
    params={"userId": 1, "_limit": 3},
    timeout=10
)
assert response.status_code == 200
posts = response.json()
assert isinstance(posts, list)
assert len(posts) <= 3
# Verify all returned posts belong to userId=1
for p in posts:
    assert p["userId"] == 1
print(f"Got {len(posts)} posts for userId=1")

# --- raise_for_status — explicit error handling ---
try:
    response = requests.get(f"{BASE_URL}/posts/99999", timeout=10)
    response.raise_for_status()   # no-op on 200; raises HTTPError on 4xx/5xx
    data = response.json()
except requests.exceptions.HTTPError as e:
    # The server returned a 4xx or 5xx — handle it explicitly
    print(f"HTTP error: {e.response.status_code} — {e}")

# --- DELETE ---
response = requests.delete(f"{BASE_URL}/posts/1", timeout=10)
assert response.status_code == 200   # JSONPlaceholder returns 200 for DELETE
print("DELETE successful")
```

**Phần 3 — Session với header dùng chung và kiểm tra request**

```python
# --- Using a Session — shared headers, cookies, connection reuse ---
session = requests.Session()
session.headers.update({
    "Content-Type": "application/json",
    "X-Test-Run": "automation-phase4",
    "X-Client-Version": "1.0"
})

response = session.get(f"{BASE_URL}/users/1", timeout=10)
assert response.status_code == 200
user = response.json()
assert "email" in user
assert "@" in user["email"]
print(f"User: {user['name']} ({user['email']})")

# --- Inspect the actual request that was sent ---
# response.request is a PreparedRequest — shows what actually went over the wire
sent_headers = response.request.headers
print(f"Sent X-Test-Run: {sent_headers.get('X-Test-Run')}")
# Useful to verify your custom headers were actually attached

# --- response.ok shorthand ---
response = session.get(f"{BASE_URL}/posts/1", timeout=10)
if response.ok:  # True for status < 400
    print("Request succeeded:", response.status_code)
else:
    print("Request failed:", response.status_code)

print("All requests tests passed!")
```

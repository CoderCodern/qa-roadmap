## Intro

<En>
API testing is the skill that separates junior QA engineers from mid-level ones. It's faster than UI testing, closer to the system's actual behaviour, and catches bugs that the UI might hide. But before you can test APIs, you need to understand HTTP — the protocol that powers every API request and response on the web.
</En>
<Vi>
Kiểm thử API là kỹ năng phân biệt kỹ sư QA cấp junior với mid-level. Nó nhanh hơn kiểm thử UI, gần hơn với hành vi thực tế của hệ thống và bắt được các lỗi mà UI có thể ẩn giấu. Nhưng trước khi bạn có thể kiểm thử API, bạn cần hiểu HTTP — giao thức cung cấp sức mạnh cho mọi API request và response trên web.
</Vi>

## Concept

<En>
**HTTP request structure:**
- **Method:** GET, POST, PUT, PATCH, DELETE, OPTIONS
- **URL:** the target endpoint
- **Headers:** metadata (Content-Type, Authorization, Accept)
- **Body:** data sent with the request (POST/PUT/PATCH only)

**HTTP response structure:**
- **Status code:** numeric result code
- **Headers:** metadata from the server (Content-Type, Set-Cookie)
- **Body:** data returned (JSON, HTML, empty)

**The most important status codes for API testing:**

| Code | Meaning | When you see it |
|------|---------|-----------------|
| 200 | OK | Successful GET, PUT, PATCH |
| 201 | Created | Successful POST (resource created) |
| 204 | No Content | Successful DELETE (empty body) |
| 400 | Bad Request | Invalid input — server rejected it |
| 401 | Unauthorized | Missing or invalid authentication |
| 403 | Forbidden | Authenticated but not permitted |
| 404 | Not Found | Resource does not exist |
| 409 | Conflict | Duplicate resource (email already taken) |
| 422 | Unprocessable Entity | Validation failed |
| 500 | Internal Server Error | Bug in the server |

**HTTP methods — what they mean semantically:**

| Method | Purpose | Idempotent? |
|--------|---------|-------------|
| GET | Read only | Yes |
| POST | Create | No |
| PUT | Replace entirely | Yes |
| PATCH | Partial update | Usually |
| DELETE | Remove | Yes |
</En>
<Vi>
**Cấu trúc HTTP request:**
- **Method:** GET, POST, PUT, PATCH, DELETE
- **URL:** endpoint mục tiêu
- **Headers:** metadata (Content-Type, Authorization)
- **Body:** dữ liệu gửi với request (chỉ POST/PUT/PATCH)

**Cấu trúc HTTP response:**
- **Status code:** mã kết quả số
- **Headers:** metadata từ server
- **Body:** dữ liệu trả về (JSON, HTML, rỗng)

**Các status code quan trọng nhất cho kiểm thử API:**

| Code | Ý nghĩa | Khi nào gặp |
|------|---------|-----------------|
| 200 | OK | GET, PUT, PATCH thành công |
| 201 | Created | POST thành công |
| 204 | No Content | DELETE thành công |
| 400 | Bad Request | Đầu vào không hợp lệ |
| 401 | Unauthorized | Thiếu xác thực |
| 403 | Forbidden | Không có quyền |
| 404 | Not Found | Tài nguyên không tồn tại |
| 500 | Internal Server Error | Lỗi trong server |

**Các HTTP method — ý nghĩa ngữ nghĩa:**

| Method | Mục đích | Idempotent? |
|--------|---------|-------------|
| GET | Chỉ đọc | Có |
| POST | Tạo mới | Không |
| PUT | Thay thế hoàn toàn | Có |
| PATCH | Cập nhật một phần | Thường |
| DELETE | Xoá | Có |
</Vi>

## Code / Demo

```python
# Simulating HTTP concepts before we use real HTTP libraries (Day 40)
# This illustrates the structure without making real network calls

def build_request(method: str, url: str, headers: dict = None, body: dict = None) -> dict:
    return {
        "method": method.upper(),
        "url": url,
        "headers": headers or {"Content-Type": "application/json"},
        "body": body,
    }

def simulate_response(status: int, body: dict = None, headers: dict = None) -> dict:
    return {
        "status_code": status,
        "headers": headers or {"Content-Type": "application/json"},
        "body": body,
    }

def is_success(response: dict) -> bool:
    return 200 <= response["status_code"] < 300

# Example: POST to create a user
create_request = build_request(
    "POST",
    "https://api.example.com/users",
    body={"email": "alice@example.com", "password": "SecurePass1"}
)
print("Request:", create_request)

# Simulated responses
success_response = simulate_response(201, {"id": 42, "email": "alice@example.com"})
auth_error = simulate_response(401, {"error": "Token missing or expired"})
not_found = simulate_response(404, {"error": "User not found"})
server_error = simulate_response(500, {"error": "Database connection failed"})

# Assertions we'd write in real tests
assert is_success(success_response)
assert not is_success(auth_error)

# Status code classification
for resp in [success_response, auth_error, not_found, server_error]:
    code = resp["status_code"]
    category = (
        "success" if 200 <= code < 300 else
        "client error" if 400 <= code < 500 else
        "server error"
    )
    print(f"  {code} → {category}")
```

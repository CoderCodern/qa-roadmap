## Intro

<En>
Making HTTP calls with `requests` is useful for exploration; combining it with `pytest` gives you a production-quality API test suite. pytest manages test discovery, fixtures, parametrize, and reporting. Today you build a structured API test project that mirrors what you'd find in a real QA role.
</En>

Thực hiện các cuộc gọi HTTP với `requests` hữu ích để khám phá; kết hợp nó với `pytest` cho bạn một bộ API test chất lượng production. pytest quản lý khám phá test, fixture, parametrize và báo cáo. Hôm nay bạn xây dựng một dự án API test có cấu trúc phản ánh những gì bạn tìm thấy trong vai trò QA thực.

## Concept

<En>
**Project structure — organise by resource, not by test type:**
```
api_tests/
├── api/
│   ├── __init__.py
│   └── client.py         # ApiClient class wrapping requests.Session
├── tests/
│   ├── __init__.py
│   ├── conftest.py       # shared fixtures — api client, base_url
│   ├── test_posts.py     # all tests for the /posts resource
│   └── test_users.py     # all tests for the /users resource
├── pytest.ini            # pytest configuration
└── requirements.txt      # requests, pytest
```

Separating by resource mirrors how REST APIs are structured. When the `/posts` endpoint breaks, you look in `test_posts.py` — not across five files mixed by test type.

**API client class — wrap `requests.Session`:**

```python
class ApiClient:
    def __init__(self, base_url: str, token: str | None = None) -> None:
        self.base_url = base_url.rstrip("/")
        self.session = requests.Session()
        self.session.headers.update({"Content-Type": "application/json"})
        if token:
            self.session.headers["Authorization"] = f"Bearer {token}"

    def get(self, path: str, **kwargs) -> requests.Response:
        return self.session.get(f"{self.base_url}{path}", **kwargs)

    def post(self, path: str, **kwargs) -> requests.Response:
        return self.session.post(f"{self.base_url}{path}", **kwargs)

    def delete(self, path: str, **kwargs) -> requests.Response:
        return self.session.delete(f"{self.base_url}{path}", **kwargs)
```

The `ApiClient` is the test equivalent of the Page Object Model from Phase 3. It centralises the base URL and auth headers — change the target server in one place, not across every test file.

**conftest.py — shared fixtures visible to all test files:**

conftest.py is a special pytest file that is automatically discovered. Any fixture defined in it is available to all test files in the same directory and below — without any import.

```python
# tests/conftest.py
import pytest
from api.client import ApiClient

BASE_URL = "https://jsonplaceholder.typicode.com"

@pytest.fixture(scope="session")
def api() -> ApiClient:
    return ApiClient(BASE_URL)
```

Any test function that declares `api` as a parameter receives this fixture automatically.

**Fixture scopes — choosing the right one:**

| Scope | Created | Destroyed | Use when |
|-------|---------|-----------|----------|
| `function` (default) | Before each test | After each test | Test modifies state (creates/deletes) |
| `module` | Once per test file | After all tests in file | Moderate sharing, file-level setup |
| `session` | Once per entire run | After all tests | Stateless client, expensive setup |

For a `requests.Session`-based ApiClient that carries no mutable state between tests, `scope='session'` is the right choice — one TCP connection pool for the whole run.

**@pytest.fixture — what it does:**

The `@pytest.fixture` decorator converts a plain function into a factory that pytest manages. pytest:
1. Calls the fixture function when a test requests it
2. Passes the return value to the test
3. Runs any teardown code after `yield` (if present) when the test finishes

```python
@pytest.fixture
def temp_user(api):
    # Setup — create a user before the test
    user = api.post("/users", json={"name": "Temp", "email": "t@t.com"}).json()
    yield user
    # Teardown — delete the user after the test
    api.delete(f"/users/{user['id']}")
```

**What to test in API tests — a systematic checklist:**

1. **Happy path** — valid request → expected 2xx response with correct body
2. **Status codes** — correct code for each scenario (200, 201, 404, 400, 422)
3. **Field presence** — all required fields exist in the response
4. **Field types** — correct Python types (`isinstance(post["id"], int)`)
5. **Business rules** — email contains "@", id is positive, role is in a valid set
6. **Error cases** — invalid input gets 4xx (not 500), error body is informative
7. **Edge cases** — empty list when no results, null fields handled, boundary ids

**@pytest.mark.parametrize — test multiple inputs with one test function:**

```python
@pytest.mark.parametrize("post_id", [1, 5, 10, 50, 100])
def test_get_valid_post_ids(api, post_id):
    response = api.get(f"/posts/{post_id}")
    assert response.status_code == 200
    assert response.json()["id"] == post_id
```

This runs 5 tests from one function. Parametrize is ideal for boundary values and happy-path coverage across multiple valid inputs.

**pytest.ini — configure pytest behaviour:**

```ini
[pytest]
addopts = -v --tb=short
log_cli = true
log_cli_level = INFO
```

- `-v` — verbose: shows each test name and result
- `--tb=short` — shorter tracebacks for API failures (no stack noise)
- `log_cli = true` — stream log output to the terminal during the run

**Class API client — bọc `requests.Session`:**

`ApiClient` là tương đương test của Page Object Model từ Phase 3. Nó tập trung base URL và auth header — thay đổi server mục tiêu ở một nơi, không phải qua mọi file test.

**conftest.py — fixture dùng chung cho tất cả file test:**

conftest.py là file pytest đặc biệt được tự động khám phá. Bất kỳ fixture nào được định nghĩa trong nó đều có sẵn cho tất cả file test trong cùng thư mục và bên dưới — không cần import nào.

**Phạm vi fixture — chọn cái đúng:**

| Phạm vi | Được tạo | Bị hủy | Dùng khi |
|-------|---------|-----------|----------|
| `function` (mặc định) | Trước mỗi test | Sau mỗi test | Test sửa đổi trạng thái (tạo/xóa) |
| `module` | Một lần mỗi file test | Sau tất cả test trong file | Chia sẻ vừa phải, setup cấp file |
| `session` | Một lần cho toàn bộ run | Sau tất cả test | Client không trạng thái, setup tốn kém |

Với ApiClient dựa trên `requests.Session` không mang trạng thái có thể thay đổi giữa các test, `scope='session'` là lựa chọn đúng.

**@pytest.fixture — nó làm gì:**

Decorator `@pytest.fixture` chuyển đổi hàm thông thường thành factory mà pytest quản lý. pytest gọi hàm fixture khi test yêu cầu nó, truyền giá trị trả về cho test, và chạy code teardown sau `yield` khi test kết thúc.

**Những gì cần kiểm thử trong API test — checklist có hệ thống:**

1. **Happy path** — request hợp lệ → response 2xx mong đợi với body đúng
2. **Status code** — mã đúng cho từng kịch bản (200, 201, 404, 400, 422)
3. **Sự hiện diện trường** — tất cả trường bắt buộc tồn tại trong response
4. **Kiểu trường** — kiểu Python đúng (`isinstance(post["id"], int)`)
5. **Quy tắc nghiệp vụ** — email chứa "@", id dương, role trong tập hợp hợp lệ
6. **Trường hợp lỗi** — đầu vào không hợp lệ nhận 4xx (không phải 500)
7. **Trường hợp biên** — list rỗng khi không có kết quả, trường null được xử lý

**@pytest.mark.parametrize — kiểm thử nhiều đầu vào với một hàm test:**

```python
@pytest.mark.parametrize("post_id", [1, 5, 10, 50, 100])
def test_get_valid_post_ids(api, post_id):
    response = api.get(f"/posts/{post_id}")
    assert response.status_code == 200
    assert response.json()["id"] == post_id
```

Cái này chạy 5 test từ một hàm. Parametrize lý tưởng cho giá trị biên và độ bao phủ happy-path trên nhiều đầu vào hợp lệ.

```python
# tests/test_posts.py
import pytest
from api.client import ApiClient

def test_get_post_by_id(api: ApiClient):
    response = api.get("/posts/1")
    assert response.status_code == 200
    post = response.json()
    # Field presence
    assert "id" in post
    assert "title" in post
    assert "body" in post
    assert "userId" in post
    # Field types
    assert isinstance(post["id"], int)
    assert isinstance(post["title"], str)
    assert len(post["title"]) > 0
    # Value assertions
    assert post["id"] == 1

def test_get_posts_list(api: ApiClient):
    response = api.get("/posts")
    assert response.status_code == 200
    posts = response.json()
    assert isinstance(posts, list)
    assert len(posts) == 100  # JSONPlaceholder always returns 100

def test_create_post(api: ApiClient):
    payload = {"title": "Test Post", "body": "Test body", "userId": 1}
    response = api.post("/posts", json=payload)
    assert response.status_code == 201
    created = response.json()
    assert "id" in created
    assert created["title"] == "Test Post"
    assert created["userId"] == 1

@pytest.mark.parametrize("post_id", [1, 5, 10, 50, 100])
def test_get_valid_post_ids(api: ApiClient, post_id: int):
    response = api.get(f"/posts/{post_id}")
    assert response.status_code == 200
    post = response.json()
    assert post["id"] == post_id

def test_get_nonexistent_post(api: ApiClient):
    response = api.get("/posts/99999")
    assert response.status_code == 404

def test_post_has_required_fields(api: ApiClient):
    response = api.get("/posts/1")
    post = response.json()
    required_fields = {"id", "userId", "title", "body"}
    missing = required_fields - set(post.keys())
    assert not missing, f"Missing fields: {missing}"
```

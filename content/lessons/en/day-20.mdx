## Intro

<En>
You don't need to be an OOP expert to write test automation, but you do need to understand classes. The Page Object Model (POM) — the standard design pattern for Playwright and Selenium test suites — is built entirely on classes. Understanding `__init__`, instance methods, and inheritance is what lets you read, write, and maintain POM-based test code.
</En>
<Vi>
Bạn không cần phải là chuyên gia OOP để viết tự động hoá test, nhưng bạn cần hiểu class. Page Object Model (POM) — mẫu thiết kế chuẩn cho bộ test Playwright và Selenium — được xây dựng hoàn toàn trên class. Hiểu `__init__`, instance method và kế thừa là điều cho phép bạn đọc, viết và bảo trì code test dựa trên POM.
</Vi>

## Concept

<En>
**Class anatomy:**
```python
class ClassName:
    class_variable = "shared by all instances"

    def __init__(self, param):     # constructor
        self.instance_variable = param  # 'self' is this instance

    def method(self):              # instance method
        return self.instance_variable

    @classmethod
    def from_dict(cls, data):     # alternative constructor
        return cls(data["param"])

    @staticmethod
    def helper():                 # utility — no access to self/cls
        return "no state needed"
```

**Key concepts for test automation:**
- `__init__` is the constructor — called when you create an instance.
- `self` refers to the current instance. Always the first parameter of instance methods.
- Instance variables are per-object state. Class variables are shared.
- `@property` creates read-only computed attributes — useful for derived test data.

**Inheritance:**
```python
class BasePage:
    def __init__(self, page):
        self.page = page

class LoginPage(BasePage):
    def login(self, email, password):
        # Uses self.page inherited from BasePage
        pass
```

**Dataclasses** (Python 3.7+) — auto-generate `__init__`, `__repr__`, and `__eq__`:
```python
from dataclasses import dataclass

@dataclass
class TestUser:
    email: str
    password: str
    role: str = "viewer"
```
</En>
<Vi>
**Cấu trúc class:**
```python
class ClassName:
    def __init__(self, param):     # constructor
        self.instance_variable = param

    def method(self):              # instance method
        return self.instance_variable
```

**Các khái niệm quan trọng cho tự động hoá test:**
- `__init__` là constructor — được gọi khi bạn tạo một instance.
- `self` tham chiếu đến instance hiện tại. Luôn là tham số đầu tiên của instance method.
- Biến instance là trạng thái của từng đối tượng. Biến class được chia sẻ.

**Kế thừa:**
```python
class BasePage:
    def __init__(self, page):
        self.page = page

class LoginPage(BasePage):
    def login(self, email, password):
        # Dùng self.page được kế thừa từ BasePage
        pass
```

**Dataclasses** (Python 3.7+) — tự tạo `__init__`, `__repr__`, và `__eq__`:
```python
from dataclasses import dataclass

@dataclass
class TestUser:
    email: str
    password: str
    role: str = "viewer"
```
</Vi>

## Code / Demo

**Pattern 1 — Basic class anatomy: `__init__`, `self`, instance methods**

<En>`__init__` runs when you create an instance and sets up its state via `self.variable = value`. Every instance method takes `self` as its first parameter — Python passes the instance automatically when you call `obj.method()`.</En>
<Vi>`__init__` chạy khi bạn tạo một instance và thiết lập trạng thái của nó qua `self.variable = value`. Mỗi instance method nhận `self` làm tham số đầu tiên — Python truyền instance đó tự động khi bạn gọi `obj.method()`.</Vi>

<CodePlayground code={`
class ApiClient:
    def __init__(self, base_url, timeout=30):
        self.base_url = base_url
        self.timeout  = timeout
        self._calls   = 0          # private by convention

    def get(self, path):
        self._calls += 1
        return f"GET {self.base_url}{path} (timeout={self.timeout}s)"

    def call_count(self):
        return self._calls

client = ApiClient("https://api.staging.example.com")
print(client.get("/users"))
print(client.get("/orders"))

assert client.call_count() == 2
assert client.base_url == "https://api.staging.example.com"
assert client.timeout  == 30
print(f"Calls made: {client.call_count()}")
print("Pattern 1 ok — __init__ and instance methods")
`} />

**Pattern 2 — Class variables, `@property`, and `__repr__`**

<En>Class variables are shared across all instances (like a URL constant). `@property` turns a method into a read-only computed attribute — callers access it without `()`. `__repr__` controls what the object looks like when printed.</En>
<Vi>Biến class được chia sẻ giữa tất cả các instance (như hằng số URL). `@property` biến một method thành thuộc tính tính toán chỉ đọc — người gọi truy cập nó mà không cần `()`. `__repr__` kiểm soát đối tượng trông như thế nào khi được in.</Vi>

<CodePlayground code={`
class LoginPage:
    URL = "/login"              # class variable — shared by all instances

    def __init__(self, base_url):
        self.base_url = base_url
        self._last_action = None

    @property
    def full_url(self):         # accessed as login.full_url, not login.full_url()
        return f"{self.base_url}{self.URL}"

    def navigate(self):
        self._last_action = f"navigated to {self.full_url}"

    def fill_credentials(self, email, password):
        self._last_action = f"filled {email}"

    def submit(self):
        if self._last_action is None:
            raise RuntimeError("Must navigate before submitting")
        return {"status": "ok", "token": "fake-token-123"}

    def __repr__(self):
        return f"LoginPage(base_url={self.base_url!r})"

login = LoginPage("https://staging.example.com")

assert login.full_url == "https://staging.example.com/login"
assert LoginPage.URL  == "/login"   # access class variable via class name

login.navigate()
login.fill_credentials("alice@example.com", "Pass1")
result = login.submit()
assert result["status"] == "ok"

print(login)          # uses __repr__
print(f"URL:    {login.full_url}")
print(f"Result: {result}")
print("Pattern 2 ok — class variable, @property, __repr__")
`} />

**Pattern 3 — Dataclasses: test data objects with no boilerplate**

<En>`@dataclass` auto-generates `__init__`, `__repr__`, and `__eq__` from the annotated fields. This makes it the cleanest way to define test user objects, API payloads, or any structured test data record.</En>
<Vi>`@dataclass` tự tạo `__init__`, `__repr__` và `__eq__` từ các trường được chú thích. Điều này làm cho nó trở thành cách sạch nhất để định nghĩa đối tượng test user, payload API hoặc bất kỳ bản ghi dữ liệu test có cấu trúc nào.</Vi>

<CodePlayground code={`
from dataclasses import dataclass

@dataclass
class TestUser:
    email:     str
    password:  str
    role:      str  = "viewer"
    is_active: bool = True

alice = TestUser("alice@example.com", "SecurePass1", role="admin")
bob   = TestUser("bob@example.com",   "AnotherPass2")

# __init__ generated — fields become constructor parameters
assert alice.role      == "admin"
assert bob.role        == "viewer"    # default value applied
assert alice.is_active == True

# __eq__ generated — compares field values
assert alice != bob

# __repr__ generated — readable output
print(alice)
print(bob)

# Can add custom methods on top of generated ones
@dataclass
class ApiPayload:
    email: str
    role:  str = "viewer"

    def to_dict(self):
        return {"email": self.email, "role": self.role}

payload = ApiPayload("charlie@example.com", "editor")
assert payload.to_dict() == {"email": "charlie@example.com", "role": "editor"}
print(f"Payload: {payload.to_dict()}")
print("Pattern 3 ok — dataclasses")
`} />

**Pattern 4 — Inheritance: BasePage → specific page objects**

<En>Inheritance lets a child class reuse all methods from the parent. In the Page Object Model, a `BasePage` holds common browser actions; each specific page inherits them and adds its own methods. The child class doesn't need to repeat the `__init__` if it doesn't add new fields.</En>
<Vi>Kế thừa cho phép class con tái sử dụng tất cả các method từ class cha. Trong Page Object Model, `BasePage` chứa các hành động trình duyệt chung; mỗi trang cụ thể kế thừa chúng và thêm các method riêng. Class con không cần lặp lại `__init__` nếu không thêm trường mới.</Vi>

<CodePlayground code={`
class BasePage:
    def __init__(self, base_url):
        self.base_url = base_url

    def navigate_to(self, path):
        return f"GET {self.base_url}{path}"

    def get_title(self):
        return f"Page at {self.base_url}"

class LoginPage(BasePage):
    URL = "/login"

    def login(self, email, password):
        self.navigate_to(self.URL)
        return {"status": "ok", "token": "fake-token"}

class DashboardPage(BasePage):
    URL = "/dashboard"

    def get_welcome_text(self, username):
        return f"Welcome, {username}!"

base = "https://staging.example.com"
login     = LoginPage(base)
dashboard = DashboardPage(base)

# Both inherit navigate_to and get_title from BasePage
print(login.navigate_to(LoginPage.URL))
print(dashboard.navigate_to(DashboardPage.URL))
print(dashboard.get_title())

# Each has its own methods
result = login.login("alice@example.com", "Pass1")
assert result["status"] == "ok"
assert dashboard.get_welcome_text("Alice") == "Welcome, Alice!"

print("Pattern 4 ok — inheritance")
`} />

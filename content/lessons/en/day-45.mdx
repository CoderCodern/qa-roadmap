## Intro

<En>
Real APIs are slow, rate-limited, unreliable, and sometimes cost money per call. Mocking lets you replace a real HTTP server with a fake one that returns pre-defined responses. This makes tests fast, deterministic, and independent of external services. `responses` is the most popular Python library for mocking HTTP calls made with the `requests` library.
</En>
<Vi>
Các API thực chậm, bị giới hạn tốc độ, không đáng tin cậy và đôi khi tốn tiền mỗi lần gọi. Mock cho phép bạn thay thế HTTP server thực bằng server giả trả về các response được định nghĩa trước. Điều này làm cho test nhanh, xác định và độc lập với các dịch vụ bên ngoài. `responses` là thư viện Python phổ biến nhất để mock các HTTP call được thực hiện với thư viện `requests`.
</Vi>

## Concept

<En>
**When to mock vs when to test against a real API:**

| Use mocks when | Use real API when |
|----------------|------------------|
| Testing unit logic (parsing, validation) | Running integration or E2E tests |
| Third-party API is rate-limited or costly | You own the API and control the environment |
| Response scenarios are hard to reproduce (e.g., 500 error, timeout) | Contract testing (verifying the schema) |
| CI must be fast and offline-capable | Acceptance testing before release |

**The `responses` library:**
```bash
pip install responses
```

```python
import responses
import requests

@responses.activate
def test_something():
    responses.add(
        responses.GET,
        "https://api.example.com/users/1",
        json={"id": 1, "email": "alice@example.com"},
        status=200,
    )
    response = requests.get("https://api.example.com/users/1")
    assert response.status_code == 200
    assert response.json()["email"] == "alice@example.com"
```

**What `@responses.activate` does:**
- Intercepts all `requests` calls within the decorated function
- Any unregistered URL raises `ConnectionError` (prevents accidental real calls)
- After the test, all registered mocks are cleared

**Mocking error scenarios:**
```python
responses.add(responses.GET, url, status=500, json={"error": "Server Error"})
responses.add(responses.GET, url, body=requests.exceptions.Timeout())
```
</En>
<Vi>
**Khi nào mock vs khi nào test với API thực:**

| Dùng mock khi | Dùng API thực khi |
|----------------|------------------|
| Kiểm thử logic đơn vị (phân tích, xác thực) | Chạy test tích hợp hoặc E2E |
| API bên thứ ba bị giới hạn hoặc tốn tiền | Bạn sở hữu API và kiểm soát môi trường |
| Kịch bản response khó tái hiện (lỗi 500, timeout) | Contract testing (xác minh schema) |
| CI phải nhanh và có thể chạy offline | Acceptance testing trước khi phát hành |

## Code / Demo

```python
import requests
import responses
import pytest

BASE_URL = "https://api.example.com"

# --- Happy path mock ---
@responses.activate
def test_get_user_success():
    responses.add(
        responses.GET,
        f"{BASE_URL}/users/1",
        json={"id": 1, "email": "alice@example.com", "role": "admin"},
        status=200,
    )
    response = requests.get(f"{BASE_URL}/users/1")
    assert response.status_code == 200
    user = response.json()
    assert user["email"] == "alice@example.com"
    assert user["role"] == "admin"

# --- 404 mock ---
@responses.activate
def test_get_nonexistent_user():
    responses.add(
        responses.GET,
        f"{BASE_URL}/users/9999",
        json={"error": "User not found"},
        status=404,
    )
    response = requests.get(f"{BASE_URL}/users/9999")
    assert response.status_code == 404
    assert "not found" in response.json()["error"].lower()

# --- Server error mock ---
@responses.activate
def test_handles_server_error():
    responses.add(
        responses.GET,
        f"{BASE_URL}/users/1",
        json={"error": "Internal Server Error"},
        status=500,
    )
    response = requests.get(f"{BASE_URL}/users/1")
    assert response.status_code == 500
    assert not response.ok

# --- Timeout mock ---
@responses.activate
def test_handles_timeout():
    responses.add(
        responses.GET,
        f"{BASE_URL}/users/1",
        body=requests.exceptions.Timeout(),
    )
    with pytest.raises(requests.exceptions.Timeout):
        requests.get(f"{BASE_URL}/users/1", timeout=5)

# --- Multiple mocks in sequence ---
@responses.activate
def test_create_then_get_user():
    responses.add(
        responses.POST,
        f"{BASE_URL}/users",
        json={"id": 42, "email": "bob@example.com"},
        status=201,
    )
    responses.add(
        responses.GET,
        f"{BASE_URL}/users/42",
        json={"id": 42, "email": "bob@example.com", "role": "viewer"},
        status=200,
    )
    # Create
    create_resp = requests.post(f"{BASE_URL}/users", json={"email": "bob@example.com"})
    assert create_resp.status_code == 201
    user_id = create_resp.json()["id"]

    # Retrieve
    get_resp = requests.get(f"{BASE_URL}/users/{user_id}")
    assert get_resp.status_code == 200
    assert get_resp.json()["id"] == user_id

print("All mock tests passed!")
```

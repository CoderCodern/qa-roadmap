## Intro

<En>
A **locator** is Playwright's way of finding elements on a page. Before you can click a button, fill an input, or assert that a message appeared, you need to locate the element first. Choosing the right locator strategy is one of the most important skills in UI automation — a fragile locator breaks your test every time the developer renames a CSS class; a good locator survives redesigns.

Playwright's locators are also **lazy and auto-waiting** — they don't query the DOM when you create them; they query it right before the action and retry until the element is ready.
</En>
<Vi>
**Locator** là cách Playwright tìm phần tử trên trang. Trước khi có thể nhấp vào nút, điền vào input, hoặc kiểm tra một thông báo đã xuất hiện, bạn cần phải tìm phần tử đó trước. Chọn đúng chiến lược locator là một trong những kỹ năng quan trọng nhất trong tự động hoá UI — một locator mỏng manh sẽ làm hỏng test mỗi khi developer đổi tên CSS class; một locator tốt sẽ tồn tại qua các lần thiết kế lại.

Locator của Playwright cũng **lười biếng và tự động chờ** — chúng không truy vấn DOM khi bạn tạo chúng; chúng truy vấn ngay trước hành động và thử lại cho đến khi phần tử sẵn sàng.
</Vi>

## Concept

<En>
**Locator priority — from most to least preferred:**

| Priority | Locator | When to use |
|----------|---------|-------------|
| 🥇 Best | `get_by_role()` | Interactive elements — buttons, links, inputs, headings |
| 🥈 Good | `get_by_label()` | Form inputs with an associated `<label>` |
| 🥈 Good | `get_by_placeholder()` | Inputs with a `placeholder` attribute |
| 🥉 OK | `get_by_text()` | Static text you need to click or assert on |
| 🥉 OK | `get_by_test_id()` | Elements with `data-testid` attribute (set by devs for testing) |
| ⚠️ Last resort | `locator("css selector")` | When no semantic locator fits |
| ❌ Avoid | `locator("xpath=...")` | Very fragile — breaks on any structural change |

**Why prefer role/label/text locators?**
They target **what the user sees and interacts with**, not implementation details like CSS class names or element IDs. A button labelled "Submit" is still called "Submit" even after a complete redesign. A CSS class like `.btn-primary-v2` can change at any commit.

**get_by_role() — the most powerful locator:**
Matches elements by their ARIA role and optional accessible name. Works for buttons, links, headings, checkboxes, textboxes, and more.

```python
# Buttons
page.get_by_role("button", name="Submit")
page.get_by_role("button", name="Delete", exact=True)   # exact=True prevents partial matches

# Links
page.get_by_role("link", name="Sign in")
page.get_by_role("link", name="Home")

# Headings
page.get_by_role("heading", name="Welcome back")
page.get_by_role("heading", level=1)   # <h1> only

# Checkboxes and radios
page.get_by_role("checkbox", name="I agree to the terms")
page.get_by_role("radio", name="Female")

# Text inputs
page.get_by_role("textbox", name="Email address")
```

**The `exact` parameter:** By default, `get_by_role()` and `get_by_text()` do a case-insensitive partial match. Pass `exact=True` when the page has multiple elements with similar text and you need one specific one:

```python
# Without exact=True: matches "Delete", "Delete account", "Delete all"
page.get_by_role("button", name="Delete")

# With exact=True: matches ONLY the button whose accessible name is exactly "Delete"
page.get_by_role("button", name="Delete", exact=True)

# Same principle for get_by_text()
page.get_by_text("Submit")              # matches "Submit form", "Submit order", etc.
page.get_by_text("Submit", exact=True)  # matches only the element whose full text is "Submit"
```

**Chaining locators to narrow scope:**
```python
# Find a button inside a specific section — avoids matching unrelated buttons
page.locator(".sidebar").get_by_role("button", name="Close")

# Find elements within a specific container (parent → child)
page.locator(".product-grid").locator(".card-title")

# Find a form field scoped to one form (when the page has multiple forms)
page.locator("form#login-form").get_by_label("Email")

# Filter by text among multiple matching elements
page.locator("li").filter(has_text="Item 2")

# Find the nth match (0-indexed)
page.locator("tr").nth(2)   # third table row

# First and last shortcuts — prefer these over [0] indexing
page.locator("li").first    # same as .nth(0) but more readable
page.locator("li").last     # same as .nth(-1)
```

**CSS locators — use sparingly:**
```python
# By ID  (IDs can be auto-generated and unstable)
page.locator("#submit-btn")

# By class (fragile — classes change with refactoring)
page.locator(".error-message")

# Attribute selectors (more stable than class names)
page.locator("[data-testid='login-form']")
page.locator("input[type='email']")
page.locator("button[disabled]")
```

**Checking how many elements match:**
```python
count = page.locator("li").count()   # returns an integer immediately (no auto-wait)
# NOTE: count() does NOT auto-wait. It returns the current count at call time.
# If you need to wait for a specific count, use:
# expect(page.locator("li")).to_have_count(5)  ← this retries until count equals 5
```
</En>
<Vi>
**Ưu tiên locator — từ tốt nhất đến kém nhất:**

| Ưu tiên | Locator | Khi nào dùng |
|----------|---------|-------------|
| 🥇 Tốt nhất | `get_by_role()` | Phần tử tương tác — nút, link, input, tiêu đề |
| 🥈 Tốt | `get_by_label()` | Input form với `<label>` liên kết |
| 🥈 Tốt | `get_by_placeholder()` | Input với thuộc tính `placeholder` |
| 🥉 Được | `get_by_text()` | Text tĩnh cần nhấp hoặc kiểm tra |
| 🥉 Được | `get_by_test_id()` | Phần tử có `data-testid` do dev đặt để test |
| ⚠️ Cuối cùng | `locator("css")` | Khi không có locator ngữ nghĩa nào phù hợp |
| ❌ Tránh | `locator("xpath=...")` | Rất mỏng manh — hỏng khi cấu trúc thay đổi |

**Tại sao ưu tiên locator theo role/label/text?**
Chúng nhắm vào **những gì người dùng nhìn thấy và tương tác**, không phải chi tiết triển khai như tên CSS class hoặc ID phần tử. Một nút có nhãn "Submit" vẫn được gọi là "Submit" dù thiết kế lại hoàn toàn. CSS class như `.btn-primary-v2` có thể thay đổi bất kỳ lúc nào.

**Tham số `exact`:** Mặc định, `get_by_role()` và `get_by_text()` khớp một phần, không phân biệt hoa thường. Dùng `exact=True` khi cần khớp chính xác:

```python
# Không có exact=True: khớp "Delete", "Delete account", "Delete all"
page.get_by_role("button", name="Delete")

# Với exact=True: chỉ khớp nút có accessible name chính xác là "Delete"
page.get_by_role("button", name="Delete", exact=True)
```

**Chaining locator để thu hẹp phạm vi:**
```python
# Tìm nút trong một section cụ thể
page.locator(".sidebar").get_by_role("button", name="Close")

# Tìm phần tử trong container cụ thể (cha → con)
page.locator(".product-grid").locator(".card-title")

# Lọc theo text trong nhiều phần tử khớp
page.locator("li").filter(has_text="Item 2")

# Phần tử đầu và cuối — ưu tiên hơn indexing [0]
page.locator("li").first    # tương đương .nth(0)
page.locator("li").last     # tương đương .nth(-1)
```

**Kiểm tra số lượng phần tử khớp:**
```python
count = page.locator("li").count()   # trả về số nguyên ngay lập tức (không auto-wait)
# LƯU Ý: count() KHÔNG auto-wait. Dùng expect().to_have_count(n) nếu cần chờ.
```

```python
# demo_locators.py
# Run with: python demo_locators.py
# Uses https://practicesoftwaretesting.com — a free QA practice site
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://practicesoftwaretesting.com")

    # --- get_by_role ---  Priority: BEST
    # Targets the ARIA role + accessible name — survives CSS class changes and DOM restructuring
    search = page.get_by_role("textbox", name="Search")
    print(f"Search input visible: {search.is_visible()}")

    # Find a link by its visible text
    sign_in = page.get_by_role("link", name="Sign in")
    print(f"Sign in link visible: {sign_in.is_visible()}")

    # Find a heading by level — useful when there is exactly one <h1>
    heading = page.get_by_role("heading", level=1)
    print(f"H1 text: {heading.text_content()}")

    # --- get_by_placeholder ---  Priority: GOOD
    # Targets the placeholder text shown when the input is empty
    # More resilient than CSS attribute selectors and maps to what users see
    page.goto("https://practicesoftwaretesting.com/auth/login")
    email_input = page.get_by_placeholder("Your email")
    print(f"Email input enabled: {email_input.is_enabled()}")

    # --- get_by_label ---  Priority: GOOD
    # Finds inputs associated with a <label> via `for` attribute or by wrapping
    password_input = page.get_by_label("Password")
    print(f"Password input found: {password_input.is_visible()}")

    # --- get_by_text ---  Priority: OK
    # Use exact=True to avoid matching elements that only contain this text as a substring
    login_heading = page.get_by_text("Login", exact=True)
    print(f"Login heading text: {login_heading.text_content()}")

    # --- CSS locator with attribute selector ---  Priority: LAST RESORT
    # More stable than class names, but still an implementation detail
    submit_btn = page.locator("input[type='submit']")
    print(f"Submit button count: {submit_btn.count()}")

    browser.close()
```

```python
# demo_chaining.py
# Demonstrates chaining locators to narrow down to specific elements.
# Chaining is key when the same locator pattern matches multiple places on the page.
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://practicesoftwaretesting.com")

    # Count all product cards on the current page
    products = page.locator(".card")
    print(f"Product cards on page: {products.count()}")

    # Get the first product card using .first — prefer this over .nth(0) for readability.
    # .first makes the intent clear at a glance: "I want the first one."
    # .nth(0) and .first are equivalent in behavior, but .first is idiomatic Playwright.
    first_card = products.first
    first_title = first_card.locator(".card-title")
    print(f"First product: {first_title.text_content()}")

    # Similarly, .last is preferred over .nth(-1)
    last_card = products.last
    last_title = last_card.locator(".card-title")
    print(f"Last product: {last_title.text_content()}")

    # Iterate over the first 3 products with .nth()
    product_items = page.locator(".card-title")
    print(f"All product titles:")
    for i in range(min(3, product_items.count())):
        print(f"  [{i}] {product_items.nth(i).text_content()}")

    # Chain: find nav links by scoping the locator to the nav element.
    # This prevents accidentally matching <a> tags in the footer or hero section.
    nav = page.locator("nav")
    nav_links = nav.locator("a")
    print(f"Nav links: {nav_links.count()}")

    browser.close()
```

```python
# tests/test_locators.py
# Run with: pytest tests/test_locators.py -v
from playwright.sync_api import Page, expect

BASE = "https://practicesoftwaretesting.com"

def test_homepage_has_search_input(page: Page):
    page.goto(BASE)
    # get_by_role — most resilient locator; survives full CSS refactors
    search = page.get_by_role("textbox", name="Search")
    expect(search).to_be_visible()   # EXPECTED: PASSED — search input found and visible
    expect(search).to_be_enabled()   # EXPECTED: PASSED — input is interactive

def test_login_form_has_email_and_password(page: Page):
    page.goto(f"{BASE}/auth/login")
    # get_by_label matches <label> text — survives any CSS/class changes
    expect(page.get_by_label("Email")).to_be_visible()      # EXPECTED: PASSED
    expect(page.get_by_label("Password")).to_be_visible()   # EXPECTED: PASSED

def test_sign_in_link_in_nav(page: Page):
    page.goto(BASE)
    sign_in = page.get_by_role("link", name="Sign in")
    expect(sign_in).to_be_visible()   # EXPECTED: PASSED — link is in the nav bar

def test_products_appear_on_homepage(page: Page):
    page.goto(BASE)
    # CSS locator acceptable here — .card is the product grid structure
    # No semantic locator uniquely identifies "product card" by role
    cards = page.locator(".card")
    count = cards.count()
    assert count > 0, f"Expected product cards, found {count}"
    # EXPECTED: PASSED — the homepage loads product cards from the API
```

## Intro

<En>
Flaky tests — tests that sometimes pass and sometimes fail without any code change — are the biggest pain in UI automation. The root cause is almost always **timing**: the test tried to interact with something that wasn't ready yet.

Playwright's auto-wait eliminates most timing issues automatically. But some situations require explicit waiting: navigations that take time, elements that appear after an API call, animations that must complete, or network requests that need to finish. Knowing when to use which waiting strategy is what separates a senior automation engineer from a beginner.

**The golden rule:** Never use `time.sleep()` in production tests. It makes tests slow without making them more reliable. Use Playwright's built-in waits instead.
</En>
<Vi>
Test không ổn định — test đôi khi pass, đôi khi fail mà không có thay đổi code nào — là nỗi đau lớn nhất trong tự động hoá UI. Nguyên nhân gốc rễ hầu như luôn là **timing**: test cố tương tác với thứ gì đó chưa sẵn sàng.

Auto-wait của Playwright loại bỏ hầu hết các vấn đề timing tự động. Nhưng một số tình huống cần chờ rõ ràng: điều hướng mất thời gian, phần tử xuất hiện sau lời gọi API, animation phải hoàn thành, hoặc network request cần kết thúc. Biết khi nào dùng chiến lược chờ nào là điều phân biệt kỹ sư automation cao cấp với người mới bắt đầu.

**Quy tắc vàng:** Không bao giờ dùng `time.sleep()` trong test thực. Nó làm test chậm mà không đáng tin hơn. Thay vào đó dùng các lệnh chờ tích hợp của Playwright.
</Vi>

## Concept

<En>
**Layer 1 — Auto-wait (built in, always on):**
Every action (`.click()`, `.fill()`, `.press()`) and every `expect()` assertion automatically waits for the target element to be ready. You don't write any wait code — it just works.

**Layer 2 — `expect()` assertions with retry:**
Playwright's `expect()` assertions poll and retry until the condition is true or the timeout expires. The default timeout is **5 seconds**.

```python
# These all retry automatically every ~100ms until timeout:
expect(locator).to_be_visible()         # wait for element to appear
expect(locator).to_be_hidden()          # wait for element to disappear
expect(locator).to_contain_text("OK")  # wait for text to appear
expect(locator).to_have_count(3)       # wait for correct number of items
expect(page).to_have_url("/dashboard") # wait for navigation

# Override the timeout for a single assertion (in milliseconds):
expect(locator).to_be_visible(timeout=10_000)  # wait up to 10s for this one assertion
expect(locator).to_contain_text("Saved", timeout=15_000)  # slow async operation
```

**Layer 3 — Explicit page waits (when you need to wait for something global):**

```python
# Wait for a specific URL pattern (supports glob and regex)
page.wait_for_url("**/dashboard")
page.wait_for_url("https://app.com/user/*")

# Wait for the page load state — choose based on what the page does:
page.wait_for_load_state("load")             # HTML + deferred resources (images, scripts)
page.wait_for_load_state("domcontentloaded") # HTML only — fast, before images load
page.wait_for_load_state("networkidle")      # no network requests for 500ms — all API calls done

# Wait for a specific element to appear — returns the ElementHandle when found
page.wait_for_selector(".success-banner")
page.wait_for_selector(".success-banner", state="visible")   # default
page.wait_for_selector(".spinner", state="hidden")           # wait for element to disappear

# Wait for a network response from a specific endpoint
with page.expect_response("**/api/users") as response_info:
    page.get_by_role("button", name="Load Users").click()
response = response_info.value
print(f"API status: {response.status}")

# Wait for navigation triggered by a click
with page.expect_navigation():
    page.get_by_role("button", name="Submit").click()
```

**`domcontentloaded` vs `networkidle` — which to use:**

- `domcontentloaded` fires when the HTML is fully parsed, before images, stylesheets, and scripts finish loading. It's **fast** — use this when you only need the page structure.
- `load` fires when all synchronously loaded resources (images, CSS) are done. Good for most traditional pages.
- `networkidle` waits until no network requests have been made for 500ms — meaning all API calls finished. **Use this for SPAs** that fetch data after the initial HTML loads. It's the slowest but most complete.

**Choosing the right wait strategy — decision guide:**

```
What are you waiting for?
│
├── An element to appear or disappear?
│   └── Use: expect(locator).to_be_visible() / .to_be_hidden()
│
├── Text to appear after an async call?
│   └── Use: expect(locator).to_contain_text("...")
│
├── The URL to change after a click?
│   └── Use: page.wait_for_url("**/path") or expect(page).to_have_url(...)
│
├── A specific number of items to load?
│   └── Use: expect(locator).to_have_count(n)
│
├── All page resources and API calls to finish?
│   └── Use: page.wait_for_load_state("networkidle")
│
├── A specific API endpoint to respond?
│   └── Use: page.expect_response() as a context manager
│
└── A custom JavaScript condition to become true?
    └── Use: page.wait_for_function("window.myFlag === true")
```

**`page.wait_for_function()` — waiting for a JavaScript condition:**
Use this when no DOM element signals readiness, but a JavaScript variable or computed state does:

```python
# Wait until a JS variable is set by the application
page.wait_for_function("window.appReady === true")

# Wait until a specific number of items are in a list
page.wait_for_function("document.querySelectorAll('.item').length >= 10")

# Wait for a custom app event to fire
page.wait_for_function("window.__lastApiCallDone === true")
```

**`page.wait_for_event()` — waiting for browser events:**
Use this to wait for browser-level events that aren't tied to a specific DOM element:

```python
# Wait for a new tab/popup to open
with page.expect_popup() as popup_info:
    page.get_by_role("button", name="Open in new tab").click()
popup = popup_info.value
popup.wait_for_load_state()
print(f"Popup URL: {popup.url}")

# Wait for a download to start
with page.expect_download() as download_info:
    page.get_by_role("button", name="Download Report").click()
download = download_info.value
download.save_as("report.pdf")
```

**Layer 4 — Polling with `expect()` (for dynamic UI):**
When content loads asynchronously (e.g., infinite scroll, live updates), `expect()` handles it:

```python
# Wait up to 15 seconds for a slow element (override default 5s)
expect(page.locator(".result-table")).to_be_visible(timeout=15_000)

# Wait for text to appear after an API call
expect(page.locator(".toast")).to_contain_text("Saved successfully")

# Wait for all items to load in an infinite scroll list
expect(page.locator(".list-item")).to_have_count(20, timeout=10_000)
```

**What to avoid:**
```python
import time

# ❌ Bad — hard-coded sleep. Slow AND still sometimes fails.
time.sleep(2)
page.locator(".button").click()

# ✅ Good — let Playwright wait intelligently
page.locator(".button").click()  # auto-waits before clicking

# ❌ Bad — checking is_visible() without retry
assert page.locator(".result").is_visible()  # fails if not yet rendered

# ✅ Good — use expect() which retries every ~100ms
expect(page.locator(".result")).to_be_visible()
```

**Timeout configuration:**
```python
# Set a global default timeout for ALL actions and assertions (milliseconds)
page.set_default_timeout(10_000)      # 10 seconds for everything

# Set a longer timeout just for navigations (page.goto, wait_for_url, etc.)
page.set_default_navigation_timeout(30_000)  # 30 seconds for navigations only

# Per-call timeout (overrides the global default for that one call)
expect(locator).to_be_visible(timeout=15_000)
page.wait_for_url("**/account", timeout=10_000)
```
</En>
<Vi>
**Lớp 1 — Auto-wait (tích hợp sẵn, luôn hoạt động):**
Mọi action (`.click()`, `.fill()`, `.press()`) và mọi assertion `expect()` tự động chờ phần tử đích sẵn sàng. Bạn không cần viết code chờ — nó tự hoạt động.

**Lớp 2 — Assertion `expect()` với retry:**
Assertion `expect()` của Playwright thử lại mỗi ~100ms cho đến khi điều kiện đúng hoặc hết timeout. Timeout mặc định là **5 giây**.

```python
# Tất cả đều tự retry:
expect(locator).to_be_visible()         # chờ phần tử xuất hiện
expect(locator).to_be_hidden()          # chờ phần tử biến mất
expect(locator).to_contain_text("OK")  # chờ text xuất hiện
expect(locator).to_have_count(3)       # chờ đúng số lượng phần tử
expect(page).to_have_url("/dashboard") # chờ điều hướng

# Override timeout cho một assertion cụ thể:
expect(locator).to_be_visible(timeout=10_000)       # chờ tối đa 10s
expect(locator).to_contain_text("Saved", timeout=15_000)  # thao tác async chậm
```

**Lớp 3 — Chờ trang rõ ràng:**

```python
# Chờ URL thay đổi
page.wait_for_url("**/dashboard")

# Chờ trạng thái tải trang:
page.wait_for_load_state("load")             # HTML + tài nguyên defer
page.wait_for_load_state("domcontentloaded") # chỉ HTML — nhanh
page.wait_for_load_state("networkidle")      # không có network request trong 500ms

# Chờ phần tử cụ thể xuất hiện — trả về ElementHandle khi tìm thấy
page.wait_for_selector(".success-banner")
page.wait_for_selector(".spinner", state="hidden")  # chờ phần tử biến mất
```

**`domcontentloaded` vs `networkidle` — nên dùng cái nào:**

- `domcontentloaded` kích hoạt khi HTML được phân tích xong, trước khi ảnh và script tải xong. **Nhanh** — dùng khi chỉ cần cấu trúc trang.
- `load` kích hoạt khi tất cả tài nguyên đồng bộ (ảnh, CSS) đã xong. Tốt cho hầu hết trang truyền thống.
- `networkidle` chờ đến khi không có network request nào trong 500ms — nghĩa là tất cả API call đã xong. **Dùng cho SPA** lấy dữ liệu sau khi HTML ban đầu tải.

**Hướng dẫn chọn chiến lược chờ:**

```
Bạn đang chờ gì?
│
├── Phần tử xuất hiện hoặc biến mất?
│   └── Dùng: expect(locator).to_be_visible() / .to_be_hidden()
│
├── Text xuất hiện sau async call?
│   └── Dùng: expect(locator).to_contain_text("...")
│
├── URL thay đổi sau khi click?
│   └── Dùng: page.wait_for_url("**/path") hoặc expect(page).to_have_url(...)
│
├── Một số lượng item cụ thể tải xong?
│   └── Dùng: expect(locator).to_have_count(n)
│
├── Tất cả tài nguyên và API call xong?
│   └── Dùng: page.wait_for_load_state("networkidle")
│
├── Một endpoint API cụ thể phản hồi?
│   └── Dùng: page.expect_response() như context manager
│
└── Điều kiện JavaScript tùy chỉnh trở thành true?
    └── Dùng: page.wait_for_function("window.myFlag === true")
```

**`page.wait_for_function()` — chờ điều kiện JavaScript:**
```python
# Chờ đến khi biến JS được set bởi ứng dụng
page.wait_for_function("window.appReady === true")

# Chờ đến khi có đủ số item trong danh sách
page.wait_for_function("document.querySelectorAll('.item').length >= 10")
```

**`page.wait_for_event()` — chờ sự kiện trình duyệt:**
```python
# Chờ tab/popup mới mở
with page.expect_popup() as popup_info:
    page.get_by_role("button", name="Open in new tab").click()
popup = popup_info.value
print(f"Popup URL: {popup.url}")
```

**Tránh:**
```python
# ❌ Xấu
time.sleep(2)
assert page.locator(".result").is_visible()  # không retry — không đáng tin

# ✅ Tốt — dùng expect() để retry
expect(page.locator(".result")).to_be_visible()
```

**Cấu hình timeout:**
```python
# Đặt timeout mặc định toàn cục cho TẤT CẢ actions và assertions
page.set_default_timeout(10_000)      # 10 giây

# Chỉ cho navigation
page.set_default_navigation_timeout(30_000)  # 30 giây

# Per-call (override global)
expect(locator).to_be_visible(timeout=15_000)
```

from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()

    # Navigate to login page and wait for the page to fully settle
    # networkidle ensures the page's API calls finish before we start interacting
    page.goto("https://practicesoftwaretesting.com/auth/login")
    page.wait_for_load_state("networkidle")
    print(f"Login page loaded: {page.url}")

    # Fill credentials — auto-wait handles element readiness
    page.get_by_label("Email").fill("customer@practicesoftwaretesting.com")
    page.get_by_label("Password").fill("welcome01")

    # Click Login — the button triggers a POST request and then a redirect
    # We MUST wait for the URL to change — the click() itself returns immediately
    page.get_by_role("button", name="Login").click()
    page.wait_for_url("**/account", timeout=10_000)  # wait up to 10s for redirect
    print(f"After login URL: {page.url}")

    # Now assert the dashboard heading is visible
    # expect() retries for 5s — safe even if the page is still rendering
    expect(page.get_by_role("heading", name="My account")).to_be_visible()
    print("Dashboard heading visible — test passed!")

    browser.close()

# Expected output:
# Login page loaded: https://practicesoftwaretesting.com/auth/login
# After login URL: https://practicesoftwaretesting.com/account
# Dashboard heading visible — test passed!

# demo_wait_dynamic.py
# Demonstrates waiting for search results that load asynchronously via API
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://practicesoftwaretesting.com")

    # Type in the search box and submit
    search = page.get_by_role("textbox", name="Search")
    search.fill("Hammer")
    search.press("Enter")

    # The results load via an API call — we must wait for them before asserting
    #
    # Option 1: networkidle — wait for ALL network activity to stop (broad, sometimes overkill)
    page.wait_for_load_state("networkidle")

    # Option 2: to_have_count — more specific: wait until a specific number of cards appear
    # Use this when you know the expected count; prefer over networkidle for SPA search results
    expect(page.locator(".card")).to_have_count(1, timeout=8_000)

    cards = page.locator(".card")
    assert cards.count() > 0, "No results found for 'Hammer'"
    print(f"Found {cards.count()} result(s) for 'Hammer'")

    # Wait for specific text to appear within the first card
    expect(page.locator(".card").first).to_contain_text("Hammer", timeout=5_000)
    print("First result contains 'Hammer' — correct!")

    browser.close()

# Expected output:
# Found 1 result(s) for 'Hammer'
# First result contains 'Hammer' — correct!

```python
# demo_wait_network.py
# Wait for a specific API call to complete before asserting
# This is the most precise technique: you get the exact API response
from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://practicesoftwaretesting.com")

    # expect_response() as a context manager:
    # 1. Playwright starts listening for the matching response BEFORE the click
    # 2. The action inside the `with` block triggers the network call
    # 3. When the `with` block exits, response_info.value holds the response
    # This guarantees zero race conditions — no sleep needed
    with page.expect_response(
        lambda response: "/products/search" in response.url and response.status == 200,
        timeout=10_000
    ) as response_info:
        # Trigger the search — this fires the API call we're listening for
        page.get_by_role("textbox", name="Search").fill("Pliers")
        page.get_by_role("textbox", name="Search").press("Enter")

    response = response_info.value
    print(f"API responded with status: {response.status}")
    print(f"API URL: {response.url}")

    # Now the results are guaranteed to be in the DOM
    # The API has responded — the UI must have rendered the data
    cards = page.locator(".card")
    print(f"Products found: {cards.count()}")

    browser.close()

# Expected output:
# API responded with status: 200
# API URL: https://practicesoftwaretesting.com/products/search?q=Pliers&...
# Products found: 3
```

## Intro

<En>
The capstone project is your chance to demonstrate everything from the past eight weeks in one cohesive, professional framework. Today you kick off the project: you scaffold the full directory structure, install dependencies, write the foundational client and fixture code, and verify your setup by getting one test green. Getting a single test green before writing more is not a shortcut — it is the discipline. Every minute you spend writing test 2 through 50 on an environment that doesn't actually work is wasted. ## Concept

<En>
**Why scaffold before writing tests — the engineering reasoning**

When you sit down to write a capstone framework, the temptation is to dive straight into test code. Resist it. The reason to scaffold first is not procedural — it is risk management. Before you write one `assert`, you want to know that:

1. Python finds your `api/` package (import path is correct)
2. `pytest` discovers your test files (naming and `testpaths` are configured)
3. The target API is reachable from your machine
4. The fixture chain works end-to-end (session → client → HTTP call)

If any of these are broken and you don't discover it until test #15, you'll waste significant debugging time — and the failure will look like a test bug when it's actually a configuration bug. Scaffolding and verifying with one test is the cheapest way to smoke-test the entire stack.

---

**Why `requirements.txt` matters for reproducibility**

A `requirements.txt` (or its equivalent) is not optional infrastructure — it is a reproducibility contract. It answers the question: "can someone else (or a CI runner) set up this project from scratch and get the same results?"

Without it:
- Your CI pipeline installs different (newer) versions of libraries and your tests break in unexpected ways
- A teammate clones your repo and can't reproduce your test failures because they're running a different `requests` version
- Six months from now, you revisit the project and can't remember which version of `allure-pytest` you used

With pinned versions in `requirements.txt`:
```
pytest==8.3.2
requests==2.32.3
jsonschema==4.23.0
allure-pytest==2.13.5
```

The environment is deterministic. Anyone running `pip install -r requirements.txt` gets the exact same dependency tree you tested with.

---

**Why `pytest.ini` matters**

`pytest.ini` centralizes configuration so that running `pytest` from the project root always works — no flags to remember, no environment variables to set. The two most important settings:

- `testpaths = tests` — tells pytest exactly where to look for tests instead of searching the whole tree (faster and prevents accidental test discovery in `venv/` or `node_modules/`)
- `addopts = -v --tb=short` — applies `-v` (verbose output showing each test name) and `--tb=short` (concise traceback for failures) to every run

Without `pytest.ini`, a new contributor would need to know the correct invocation. With it, `pytest` just works.

---

**Why session-scoped auth fixture — the engineering reasoning**

ReqRes.in's `POST /login` returns a token. Your test suite needs that token for any authenticated endpoint. You have two choices for how to provide it:

**Option A — function scope (default)**
```python
@pytest.fixture  # scope="function" is the default
def auth_api():
    # This runs before EVERY SINGLE test function that requests it
    client.post("/login", ...)
```
With 30 tests that request `auth_api`, this makes 30 login calls. For ReqRes.in it doesn't matter much, but for a real application with rate limiting, a slow auth service, or billable API calls, this is wasteful and fragile.

**Option B — session scope**
```python
@pytest.fixture(scope="session")
def auth_api():
    # This runs ONCE for the entire test session
    client.post("/login", ...)
```
One login call. The token is reused across all tests that need it. This is the correct choice for any fixture that produces expensive-to-acquire, reusable state.

The general rule: use the widest scope that is still correct. Session > module > class > function.

---

**Why `api/client.py` is a wrapper and not just raw `requests` calls**

Wrapping `requests.Session` in an `ApiClient` class gives you four things that raw `requests.get(url)` calls don't:

1. **Base URL centralization** — change `https://reqres.in/api` in one place, not in 50 test files
2. **Auth header injection** — set `Authorization: Bearer <token>` once at client construction; every request carries it automatically
3. **Session reuse** — `requests.Session` reuses the TCP connection between calls (connection pooling), which is meaningfully faster than creating a new connection per call
4. **Testability** — you can mock `ApiClient` in unit tests without touching the network

The capstone `ApiClient` is intentionally minimal — no retry logic, no response parsing, no business logic. It is a thin HTTP adapter, nothing more. Business logic belongs in tests, not in the client.

**Tại sao `scope="session"` cho auth fixture**

Với 30 test yêu cầu `auth_api`, function scope thực hiện 30 lần đăng nhập. Session scope thực hiện một lần duy nhất. Quy tắc chung: dùng scope rộng nhất vẫn còn đúng. Session > module > class > function.

---

**Tại sao `api/client.py` là wrapper và không phải là lời gọi `requests` thuần**

Bọc `requests.Session` trong class `ApiClient` cho bạn bốn thứ mà lời gọi `requests.get(url)` thuần không có:

1. **Tập trung hóa base URL** — thay đổi một chỗ, không phải 50 file test
2. **Tiêm auth header** — đặt `Authorization: Bearer <token>` một lần khi khởi tạo client; mọi request tự động mang nó
3. **Tái sử dụng session** — `requests.Session` tái sử dụng kết nối TCP giữa các lần gọi (connection pooling)
4. **Khả năng test** — bạn có thể mock `ApiClient` trong unit test mà không cần chạm đến mạng

# api/client.py
#
# A thin wrapper around requests.Session that centralizes the base URL,
# injects auth headers automatically, and provides one method per HTTP verb.
# This class contains zero business logic — it is purely an HTTP adapter.
# All assertions and validations belong in the test files, not here.

import requests


class ApiClient:
    """
    Reusable HTTP client for the capstone test suite.

    Usage:
        client = ApiClient("https://reqres.in/api")
        resp = client.get("/users/2")

        # Authenticated client (token injected automatically into every request):
        auth_client = ApiClient("https://reqres.in/api", token="QpwL5tpe83ilfN2")
        resp = auth_client.get("/users/2")
    """

    def __init__(self, base_url: str, token: str | None = None) -> None:
        self._session = requests.Session()
        self._session.headers.update({
            "Content-Type": "application/json",
            "Accept": "application/json",
        })
        if token:
            self._session.headers["Authorization"] = f"Bearer {token}"
        # Strip trailing slash so paths like "/users/1" always work correctly
        self.base_url = base_url.rstrip("/")

    def _url(self, path: str) -> str:
        """Prepend the base URL to a relative path."""
        return f"{self.base_url}{path}"

    def get(self, path: str, **kwargs) -> requests.Response:
        return self._session.get(self._url(path), **kwargs)

    def post(self, path: str, **kwargs) -> requests.Response:
        return self._session.post(self._url(path), **kwargs)

    def put(self, path: str, **kwargs) -> requests.Response:
        return self._session.put(self._url(path), **kwargs)

    def patch(self, path: str, **kwargs) -> requests.Response:
        return self._session.patch(self._url(path), **kwargs)

    def delete(self, path: str, **kwargs) -> requests.Response:
        return self._session.delete(self._url(path), **kwargs)

    def close(self) -> None:
        """Explicitly close the underlying session (releases TCP connections)."""
        self._session.close()
```

# tests/conftest.py
#
# Session-scoped fixtures are defined here so they are available to ALL test
# files under tests/ without needing to import anything.
#
# Fixture scope quick reference:
#   scope="function"  — created/destroyed for EVERY test function (default)
#   scope="class"     — created/destroyed once per test class
#   scope="module"    — created/destroyed once per test file
#   scope="session"   — created/destroyed once for the entire pytest run
#
# Use "session" for expensive, reusable state (HTTP clients, auth tokens).
# Use "function" for data that must be fresh per test (created resources, etc).

import pytest
from api.client import ApiClient

BASE_URL = "https://reqres.in/api"


@pytest.fixture(scope="session")
def api() -> ApiClient:
    """
    Unauthenticated API client for the entire test session.

    Session scope: the client is created once and reused by all tests that
    request it. This avoids re-initializing the requests.Session on every test,
    which would waste the connection pool and slow down the suite.
    """
    client = ApiClient(BASE_URL)
    yield client
    client.close()  # release TCP connections when the session ends


@pytest.fixture(scope="session")
def auth_api() -> ApiClient:
    """
    Authenticated API client — logs in once and reuses the token for all tests.

    Why session scope?
    - POST /login is a real network call. With scope="function" (the default),
      a suite of 30 tests using auth_api would make 30 login calls.
    - With scope="session", the login call happens once. The token is valid
      for the entire run. This is both faster and less fragile.

    The assert on resp.status_code here is intentional: if login fails,
    pytest raises an error during fixture setup, which makes the failure
    reason immediately clear rather than burying it inside a test body.
    """
    client = ApiClient(BASE_URL)
    resp = client.post("/login", json={
        "email": "eve.holt@reqres.in",
        "password": "cityslicka",
    })
    assert resp.status_code == 200, (
        f"Auth fixture: login failed with {resp.status_code}. "
        f"Response: {resp.text}"
    )
    token = resp.json()["token"]

    # Return a new client pre-configured with the token.
    # This client injects `Authorization: Bearer <token>` on every request.
    auth_client = ApiClient(BASE_URL, token=token)
    yield auth_client
    auth_client.close()
```

# tests/api/test_users.py
#
# Run with: pytest tests/ -v
# Run with Allure: pytest tests/ -v --alluredir=allure-results
#                 allure serve allure-results
#
# These tests target https://reqres.in/api — a public mock API.
# No credentials or setup required for the unauthenticated tests.

import allure
import pytest
from jsonschema import validate, ValidationError

from api.client import ApiClient


# ---------------------------------------------------------------------------
# JSON Schema definitions
# Schema validation catches contract violations that status code checks miss.
# Example: the API returns 200 but renames "first_name" to "firstName" —
# the status check passes but the schema check catches the breaking change.
# ---------------------------------------------------------------------------

USER_SCHEMA = {
    "type": "object",
    "required": ["id", "email", "first_name", "last_name", "avatar"],
    "properties": {
        "id":         {"type": "integer"},
        "email":      {"type": "string", "format": "email"},
        "first_name": {"type": "string", "minLength": 1},
        "last_name":  {"type": "string", "minLength": 1},
        "avatar":     {"type": "string", "format": "uri"},
    },
    "additionalProperties": False,
}

LIST_RESPONSE_SCHEMA = {
    "type": "object",
    "required": ["page", "per_page", "total", "total_pages", "data"],
    "properties": {
        "page":        {"type": "integer"},
        "per_page":    {"type": "integer"},
        "total":       {"type": "integer"},
        "total_pages": {"type": "integer"},
        "data":        {"type": "array", "items": USER_SCHEMA},
    },
}


# ---------------------------------------------------------------------------
# Test class
# ---------------------------------------------------------------------------

@allure.epic("ReqRes.in Capstone")
@allure.feature("User API")
class TestUsers:

    @allure.story("List users")
    @allure.severity(allure.severity_level.CRITICAL)
    @allure.title("GET /users?page=1 returns paginated list with correct schema")
    def test_list_users_page_1(self, api: ApiClient):
        """Verify that the paginated user list endpoint returns valid data."""
        with allure.step("GET /users?page=1"):
            response = api.get("/users", params={"page": 1})

        with allure.step("Verify 200 status code"):
            assert response.status_code == 200, (
                f"Expected 200, got {response.status_code}. Body: {response.text}"
            )

        with allure.step("Parse response body"):
            body = response.json()

        with allure.step("Validate list response schema"):
            # jsonschema.validate raises ValidationError if the response
            # doesn't match the schema — catching contract regressions early.
            validate(instance=body, schema=LIST_RESPONSE_SCHEMA)

        with allure.step("Verify pagination metadata"):
            assert body["page"] == 1
            assert body["per_page"] > 0
            assert body["total"] > 0
            assert len(body["data"]) > 0, "Expected at least one user in the list"

    @allure.story("Retrieve user")
    @allure.severity(allure.severity_level.CRITICAL)
    @allure.title("GET /users/2 returns correct user data and schema")
    def test_get_user_by_id(self, api: ApiClient):
        """Verify that a valid user ID returns the user object with correct schema."""
        with allure.step("GET /users/2"):
            response = api.get("/users/2")

        with allure.step("Verify 200 status code"):
            assert response.status_code == 200

        with allure.step("Validate user schema"):
            data = response.json()["data"]
            validate(instance=data, schema=USER_SCHEMA)

        with allure.step("Verify user ID matches requested ID"):
            assert data["id"] == 2

    @allure.story("Retrieve user")
    @allure.severity(allure.severity_level.NORMAL)
    @allure.title("GET /users/9999 returns 404 for non-existent user")
    def test_get_user_not_found(self, api: ApiClient):
        """Verify that requesting a non-existent user ID returns 404."""
        with allure.step("GET /users/9999"):
            response = api.get("/users/9999")

        with allure.step("Verify 404 status code"):
            assert response.status_code == 404, (
                f"Expected 404 for non-existent user, got {response.status_code}"
            )

    @allure.story("Create user")
    @allure.severity(allure.severity_level.CRITICAL)
    @allure.title("POST /users creates a user and returns 201 with id and createdAt")
    def test_create_user(self, api: ApiClient):
        """Verify that creating a user returns 201 with the expected fields."""
        payload = {"name": "QA Engineer", "job": "Test Automation"}

        with allure.step("POST /users with valid payload"):
            response = api.post("/users", json=payload)

        with allure.step("Verify 201 status code"):
            assert response.status_code == 201, (
                f"Expected 201, got {response.status_code}. Body: {response.text}"
            )

        with allure.step("Verify response contains expected fields"):
            body = response.json()
            assert "id" in body, "Response must contain 'id'"
            assert "createdAt" in body, "Response must contain 'createdAt'"
            assert body["name"] == payload["name"]
            assert body["job"] == payload["job"]

    @allure.story("Retrieve user")
    @allure.severity(allure.severity_level.NORMAL)
    @allure.title("GET /users?page=N returns correct page metadata for pages 1 and 2")
    @pytest.mark.parametrize("page", [1, 2])
    def test_list_users_pagination(self, api: ApiClient, page: int):
        """Verify that the page metadata in the response matches the requested page."""
        with allure.step(f"GET /users?page={page}"):
            response = api.get("/users", params={"page": page})

        assert response.status_code == 200
        assert response.json()["page"] == page

# After running, execute: pytest tests/ -v
# You should see at least 1 PASSED test before writing any more.

import subprocess
import sys
import os

def run(cmd: str, check: bool = True) -> subprocess.CompletedProcess:
    """Run a shell command and print it."""
    print(f"  $ {cmd}")
    result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
    if check and result.returncode != 0:
        print(f"  ERROR: {result.stderr.strip()}")
        sys.exit(1)
    if result.stdout.strip():

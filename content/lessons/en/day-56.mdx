## Concept

<En>
**What you have built across 56 days:**

| Phase | Weeks | Core skills |
|-------|-------|-------------|
| 1 — Fundamentals | 1 | Testing theory, test cases, bug lifecycle, SDLC, test pyramid |
| 2 — Python | 2–3 | Variables, functions, OOP, exceptions, file I/O |
| 3 — Playwright | 4–5 | Browser automation, POM, fixtures, CI |
| 4 — API Testing | 6–7 | HTTP, pytest + requests, JSON Schema, mocking, negative testing |
| 5 — Capstone | 8 | Integrated framework, Allure, test plan, CI pipeline |

**Making your capstone portfolio-ready:**

1. **Public GitHub repository** — clean history, no secrets committed
2. **README** — what is tested, prerequisites, `pip install -r requirements.txt`, `pytest tests/ -v`, CI badge
3. **CI badge** — paste the GitHub Actions badge URL in your README so recruiters see green instantly
4. **Allure report screenshot** — include a screenshot of a passing Allure report in the README
5. **Test plan document** — attach `TEST_PLAN.md` so readers see your thinking process, not just the code

**Certification path:**

- **ISTQB Foundation Level (CTFL)** — the most widely recognised entry-level QA certification globally. Validates test design, bug reporting, and SDLC knowledge. Study time: 4–8 weeks after this course.
- **ISTQB Test Automation Engineer (CT-TAE)** — advanced certification for automation specialists. Covers framework design, tool selection, and CI/CD integration. Recommended after 6–12 months of hands-on automation work.

**QA career paths:**

| Role | Focus | Typical next step |
|------|-------|-------------------|
| QA Engineer (Manual) | Test cases, exploratory | QA Automation Engineer |
| QA Automation Engineer | pytest, Playwright, API | Senior QA / QA Lead |
| QA Lead | Strategy, mentoring | QA Manager / Test Architect |
| SDET | Test infrastructure, CI | DevOps / Platform Engineering |

**What makes a senior QA engineer:**
- Writes tests that prevent regressions, not just tests that pass
- Understands the system well enough to predict where bugs hide
- Treats the test framework as a product — designs for maintainability
- Communicates risk in business terms, not just pass/fail counts
- Advocates for quality in planning meetings, not only after code is written
</En>
<Vi>
**Những gì bạn đã xây dựng trong 56 ngày:**

| Phase | Tuần | Kỹ năng cốt lõi |
|-------|-------|-------------|
| 1 — Cơ bản | 1 | Lý thuyết test, test case, vòng đời lỗi, SDLC, tháp test |
| 2 — Python | 2–3 | Biến, hàm, OOP, ngoại lệ, file I/O |
| 3 — Playwright | 4–5 | Tự động hoá trình duyệt, POM, fixture, CI |
| 4 — API Testing | 6–7 | HTTP, pytest + requests, JSON Schema, mocking, test tiêu cực |
| 5 — Capstone | 8 | Framework tích hợp, Allure, kế hoạch test, CI pipeline |

**Con đường chứng chỉ:**
- **ISTQB Foundation Level (CTFL)** — chứng chỉ QA cấp cơ bản được công nhận rộng rãi nhất trên toàn cầu.
- **ISTQB Test Automation Engineer (CT-TAE)** — chứng chỉ nâng cao cho chuyên gia tự động hoá.

**Điều làm nên kỹ sư QA cấp senior:**
- Viết test ngăn ngừa hồi quy, không chỉ test vượt qua
- Hiểu hệ thống đủ để dự đoán nơi lỗi ẩn náu
- Coi framework test như một sản phẩm — thiết kế cho khả năng bảo trì
- Truyền đạt rủi ro theo ngôn ngữ kinh doanh, không chỉ đếm pass/fail
- Vận động cho chất lượng trong các cuộc họp lập kế hoạch, không chỉ sau khi code được viết
</Vi>

## Code / Demo

```markdown
# README.md template for your capstone project

## Capstone QA Framework

Automated test suite for [Target App Name] covering API and UI flows.

## What is tested

**API (ReqRes.in):**
- User CRUD: list, get by ID, create, update, delete
- Authentication: login, register, invalid credentials
- Pagination: page 1 and 2

**UI (Sauce Demo):**
- Login: valid credentials, wrong password
- Cart: add item, verify cart count

## Prerequisites

- Python 3.11+
- Google Chrome (for UI tests)

## Installation

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
```

## Running tests

```bash
# All tests
pytest tests/ -v

# API only
pytest tests/api/ -v

# UI only
pytest tests/ui/ -v

# With Allure report
pytest tests/ --alluredir=allure-results
allure serve allure-results
```

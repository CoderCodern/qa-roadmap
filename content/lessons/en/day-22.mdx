## Intro

<En>
Browser automation means writing code that controls a real web browser — clicking buttons, filling forms, navigating pages — exactly what a human tester does, but executed by a script in milliseconds. This is the foundation of modern UI test automation.

Playwright is the industry-leading browser automation library. Released by Microsoft in 2020, it has quickly become the preferred choice over older tools like Selenium because it is faster, more reliable, and handles modern web apps (SPAs, dynamic content) far better. Today you install it and run your very first automated browser script.
</En>
<Vi>
Tự động hoá trình duyệt có nghĩa là viết code điều khiển trình duyệt web thực — nhấp nút, điền form, điều hướng trang — chính xác những gì người kiểm thử làm, nhưng được thực thi bởi script trong mili giây. Đây là nền tảng của kiểm thử UI tự động hiện đại.

Playwright là thư viện tự động hoá trình duyệt hàng đầu trong ngành. Được Microsoft phát hành năm 2020, nó nhanh chóng trở thành lựa chọn ưa thích hơn các công cụ cũ như Selenium vì nhanh hơn, đáng tin cậy hơn và xử lý các ứng dụng web hiện đại (SPA, nội dung động) tốt hơn nhiều. Hôm nay bạn cài đặt và chạy script trình duyệt tự động đầu tiên.
</Vi>

## Concept

<En>
**Why Playwright over Selenium?**

| Feature | Playwright | Selenium |
|---------|-----------|---------|
| Auto-wait | ✅ Built-in — waits for elements automatically | ❌ Manual waits required |
| Speed | Fast — uses CDP protocol directly | Slower — extra WebDriver layer |
| Modern browsers | Chromium, Firefox, WebKit (Safari engine) | Same, but less stable WebKit |
| Network interception | ✅ Built-in (`page.route()`) | ❌ Needs third-party proxy |
| Multiple contexts | ✅ Parallel isolated sessions in one process | ❌ One session per driver |
| Python support | First-class (`playwright.sync_api`) | First-class |

**Speed difference explained:** Selenium routes every command through a separate WebDriver process — an extra network hop per action. Playwright communicates directly with the browser via the Chrome DevTools Protocol (CDP) in a single hop. For a 100-step test, this difference adds up fast: Playwright avoids 100 round-trips through an intermediary.

**The four core objects — how they relate:**

```
Playwright
  └── Browser  (one browser binary: Chromium, Firefox, or WebKit)
        └── BrowserContext  (isolated session: own cookies, storage, auth)
              └── Page  (one browser tab)
```

- **Playwright** — the entry point. Manages browser binaries.
- **Browser** — one running browser instance. Shared across contexts.
- **BrowserContext** — like a private window. Each context has completely separate cookies, `localStorage`, and session state. Great for testing "logged-in user" and "guest" simultaneously. When you create a new context, it starts completely fresh — no cookies, no localStorage, no session data whatsoever.
- **Page** — one tab. This is what you interact with most.

**Installation — two separate commands (both required):**
```bash
pip install playwright          # installs the Python library, bindings, and CLI tool
playwright install chromium    # downloads the Chromium browser binary (~150 MB)
```

These are separate steps for a reason: `pip install playwright` gives you the Python API but no browser. `playwright install chromium` downloads the actual browser binary that Playwright controls. You must run both before you can automate anything.

To install all three browsers (Chromium, Firefox, WebKit) at once:
```bash
playwright install  # installs all three browsers
```

To install only a specific browser:
```bash
playwright install chromium   # ~150 MB — recommended for most use cases
playwright install firefox    # ~80 MB
playwright install webkit     # ~60 MB
```

**Two API styles — choose based on your context:**
```python
# Synchronous (simpler — use this for tests, scripts, and CLI tools)
from playwright.sync_api import sync_playwright

# Asynchronous (required when integrating with async frameworks)
from playwright.async_api import async_playwright
```

Use the **sync API** unless you are integrating Playwright into an async Python application (e.g., a FastAPI server that runs browser automation on demand). For all pytest-based tests, use the sync API — pytest itself is synchronous and the `pytest-playwright` plugin is built on top of `sync_playwright`.

**Headless vs Headed:**
- **Headless** (default): browser runs without a visible window — faster, used in CI pipelines.
- **Headed**: browser window is visible — use `headless=False` when debugging failing tests.
- **slow_mo**: add `slow_mo=600` (ms) to insert a delay after every single action (click, fill, navigate, keyboard). This lets you watch the browser work in slow motion in a headed window and see each step clearly.
</En>
<Vi>
**Tại sao dùng Playwright thay vì Selenium?**

| Tính năng | Playwright | Selenium |
|---------|-----------|---------|
| Auto-wait | ✅ Tích hợp sẵn — tự động chờ phần tử | ❌ Phải chờ thủ công |
| Tốc độ | Nhanh — dùng giao thức CDP trực tiếp | Chậm hơn — có thêm lớp WebDriver |
| Trình duyệt hiện đại | Chromium, Firefox, WebKit | Giống nhau nhưng WebKit kém ổn định hơn |
| Chặn network | ✅ Tích hợp sẵn (`page.route()`) | ❌ Cần proxy bên thứ ba |
| Nhiều context | ✅ Phiên song song trong một tiến trình | ❌ Một phiên mỗi driver |

**Sự khác biệt về tốc độ:** Selenium định tuyến mỗi lệnh qua một tiến trình WebDriver riêng — thêm một lần network hop cho mỗi hành động. Playwright giao tiếp trực tiếp với trình duyệt qua Chrome DevTools Protocol (CDP) trong một lần. Với test 100 bước, Playwright tránh được 100 round-trip qua intermediary.

**Bốn đối tượng cốt lõi:**

```
Playwright
  └── Browser  (một trình duyệt: Chromium, Firefox, hoặc WebKit)
        └── BrowserContext  (phiên độc lập: cookie, storage, xác thực riêng)
              └── Page  (một tab trình duyệt)
```

- **Browser** — một instance trình duyệt đang chạy.
- **BrowserContext** — như cửa sổ ẩn danh — cookie, localStorage và trạng thái phiên hoàn toàn riêng biệt. Mỗi context mới bắt đầu hoàn toàn trống — không có cookie, không có localStorage, không có dữ liệu phiên nào cả.
- **Page** — một tab trình duyệt. Đây là đối tượng bạn tương tác nhiều nhất.

**Cài đặt — hai lệnh riêng biệt (cả hai đều cần thiết):**
```bash
pip install playwright          # cài thư viện Python, bindings và CLI tool
playwright install chromium     # tải binary trình duyệt Chromium (~150 MB)
```

`pip install playwright` cho bạn Python API nhưng không có trình duyệt. `playwright install chromium` tải binary trình duyệt thực sự mà Playwright điều khiển. Phải chạy cả hai trước khi tự động hoá bất cứ thứ gì.

**Hai kiểu API — chọn dựa trên ngữ cảnh:**
```python
# Đồng bộ (đơn giản hơn — dùng cho test, script, và CLI)
from playwright.sync_api import sync_playwright

# Bất đồng bộ (cần khi tích hợp với framework async)
from playwright.async_api import async_playwright
```

Dùng **sync API** trừ khi bạn tích hợp Playwright vào ứng dụng Python async (ví dụ: FastAPI server chạy tự động hoá trình duyệt theo yêu cầu). Với tất cả test dựa trên pytest, dùng sync API.

**Headless vs Headed:**
- **Headless** (mặc định): trình duyệt chạy không có cửa sổ hiển thị — nhanh hơn, dùng trong CI.
- **Headed**: cửa sổ trình duyệt hiển thị — dùng `headless=False` khi debug.
- **slow_mo**: thêm `slow_mo=600` (ms) để chèn độ trễ sau mỗi hành động (click, fill, navigate). Cho phép bạn xem trình duyệt làm việc trong chế độ chậm và nhìn rõ từng bước.
</Vi>

## Code / Demo

<En>

**Part 1 — Basic script: navigate, assert, screenshot**

</En>
<Vi>

**Phần 1 — Script cơ bản: điều hướng, kiểm tra, chụp màn hình**

</Vi>

```python
# demo_basic.py
# Run with: python demo_basic.py
from playwright.sync_api import sync_playwright

# The `with` block guarantees cleanup: when the block exits (normally or
# via exception), sync_playwright.__exit__() stops browser processes,
# closes file handles, and frees memory. Without this, orphaned browser
# processes accumulate and consume system resources.
with sync_playwright() as p:
    # 1. Launch a browser (headless=True = no visible window)
    browser = p.chromium.launch(headless=True)

    # 2. Create an isolated session (like a private/incognito window)
    #    Each new_context() starts with empty cookies and empty localStorage.
    context = browser.new_context()

    # 3. Open a tab
    page = context.new_page()

    # 4. Navigate to a URL
    page.goto("https://example.com")

    # 5. Read page metadata
    print(f"Title : {page.title()}")
    print(f"URL   : {page.url}")

    # 6. Find an element and read its text
    heading = page.locator("h1")
    print(f"H1    : {heading.text_content()}")

    # 7. Count all links on the page
    link_count = page.locator("a").count()
    print(f"Links : {link_count}")

    # 8. Save a screenshot
    page.screenshot(path="screenshot.png")
    print("Screenshot saved → screenshot.png")

    # 9. Clean up — always close context before browser.
    #    context.close() releases cookies, storage, and network state for this session.
    #    browser.close() shuts down the browser process entirely.
    #    The `with` block also handles this automatically if you forget.
    context.close()
    browser.close()

# Expected output:
# Title : Example Domain
# URL   : https://example.com/
# H1    : Example Domain
# Links : 1
# Screenshot saved → screenshot.png
```

**Part 2 — Headed mode with slow_mo: watch the browser in real time**

</En>
<Vi>

**Phần 2 — Chế độ headed với slow_mo: xem trình duyệt hoạt động trực tiếp**

</Vi>

```python
# demo_headed.py
# Run with: python demo_headed.py
# A real Chrome window will open — watch it navigate!
from playwright.sync_api import sync_playwright
import time

with sync_playwright() as p:
    # headless=False → shows the browser window so you can watch
    # slow_mo=800   → inserts an 800ms pause after EVERY action
    #                 (click, fill, navigate, keyboard press — all of them)
    #                 This makes each step clearly visible in the window.
    browser = p.chromium.launch(headless=False, slow_mo=800)
    page = browser.new_page()

    page.goto("https://example.com")
    print(f"Opened: {page.url}")

    time.sleep(1)  # extra pause to see the loaded page before clicking

    # Click the "More information..." link
    # With slow_mo=800, you can clearly see the click happen and the
    # page navigate before the next action runs.
    page.locator("a").click()
    time.sleep(1)

    print(f"After click: {page.url}")
    browser.close()
```

<En>

**Part 3 — Two isolated contexts: simulate two users simultaneously**

</En>
<Vi>

**Phần 3 — Hai context độc lập: mô phỏng hai người dùng đồng thời**

</Vi>

```python
# demo_contexts.py
# Demonstrates that BrowserContexts are completely isolated.
# This is the key mechanism for testing multiple users simultaneously.
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)

    # --- User A (e.g., logged-in admin) ---
    ctx_a = browser.new_context()
    page_a = ctx_a.new_page()
    page_a.goto("https://example.com")
    # Store a value in localStorage for User A's session
    page_a.evaluate("localStorage.setItem('user', 'Alice')")
    alice_value = page_a.evaluate("localStorage.getItem('user')")

    # --- User B (e.g., anonymous guest) ---
    # ctx_b is a completely separate session — new context = blank slate.
    # User B's localStorage has nothing — ctx_a's setItem never touched it.
    ctx_b = browser.new_context()
    page_b = ctx_b.new_page()
    page_b.goto("https://example.com")
    # User B's localStorage is completely separate — nothing was set here
    bob_value = page_b.evaluate("localStorage.getItem('user')")

    print(f"User A localStorage['user']: {alice_value}")  # Alice
    # bob_value is None — proves the two contexts are fully isolated.
    # If contexts shared state, this would incorrectly return 'Alice'.
    print(f"User B localStorage['user']: {bob_value}")    # None

    ctx_a.close()
    ctx_b.close()
    browser.close()

# Expected output:
# User A localStorage['user']: Alice
# User B localStorage['user']: None
```
